# 论文阅读与积累工作流

为 DeepSeek Harness 准备的八阶段、十份业务 Skill：从研究方向与选文开始，支持场景解释、原文陪读、个人判断、技术笔记、写作素材和关系图。多数论文可以止于筛读，无需每篇完成全部阶段。

## 工具分工

| 工具 | 用途 |
|---|---|
| DeepSeek＋DeepSeek Harness | 对话与执行业务 Skill，保存和恢复任务 |
| Undermind MCP | 实际找文、补搜、参考文献与引文追踪 |
| Zotero CLI＋Skill | 定位已有论文与译稿，保存选文记录、三笔记和分类 |
| 本地 MinerU CLI＋Skill | 按页解析 PDF、保存定位并导出原图供核对 |
| Obsidian 官方 CLI＋Skill | 文献导航、写作素材及关系 Canvas |
| 用户已有翻译工具 | 生成译稿，与原稿按同篇论文关联 |

本仓库提供业务规则与安装脚本。上述应用、工具 Skill、模型路由和账户连接需在使用环境中分别配置；安装脚本不会安装第三方运行时、写入 API 密钥或改变权限设置。辅助工具调用条件见 [工具接入说明](workflow搭建组件/发布工具/工具接入.md)。

## 安装业务 Skill

需要 Python 3.10+、已安装的 DeepSeek Harness。默认使用用户目录下的 `.dsh`；自定义位置用 `--dsh-home`。

```powershell
python workflow搭建组件/发布工具/install.py --check
python workflow搭建组件/发布工具/install.py
```

已有同名 `paper-*` 入口时脚本会停止。确认替换后可加 `--replace`，旧入口会自动备份；任何已读论文、笔记或任务状态均不在替换范围。

安装将完整规则及引用资源复制到 `.dsh/integrations/paper-workflow/releases/1.0.0/`，再在默认 `.dsh/skills/` 创建十份发现入口，避免桌面预设未加载宿主层自定义目录的问题。业务规则与具体命令分开，按需加载实际工具 Skill。

## 从空白开始

选两个不同的本地目录，例如：

```powershell
python workflow搭建组件/发布工具/init_workspace.py --workspace ./本地数据/论文工作区 --vault ./本地数据/论文知识库
```

脚本只创建空状态，已有状态文件会触发停止。用 Obsidian 打开新库，再在 Harness 选择新工作区并新建会话，输入：

> 开始新的论文工作流。先和我对齐这次的研究目标，再决定找文或阅读哪篇论文。

已选论文时直接提供 Zotero 中的题名；需要新方向时说明领域。关闭会话前保存的正文、索引和当前入口供下次恢复；换论文或任务会保留各自记录。无需记住十个 Skill 名称。

## 阶段

1. 对齐背景、任务、最新规则与已有材料；更新记录由独立 Skill 负责。
2. 用 Undermind 找论文并筛选，保留真实检索返回与判断依据。
3. 依据实际材料解释问题与核心机制，由用户决定阅读深度。
4. 沿信息流陪读关键模块，用户复述后纠偏，按需补基础。
5. 独立记录个人创新／用途、准确技术方法、个人认为的不足。
6. 按问题／方法分类，按需积累文章的组织与分析写法。
7. 保留经核对的短参考句、语境与来源，区分引用和表达借鉴。
8. 从固定材料版本归档并逐项回读，按有依据的关系增量更新图谱。

## 数据与边界

Git 仅跟踪通用发布包、脚本和说明。个人学习档案、论文 PDF、Zotero 数据、Obsidian 库、测试运行记录、缓存和凭据留在本地；本仓库没有任何已选论文或试用进度。

AI 解释不等于用户已掌握，AI 候选不冒充个人判断；工具安装或进程退出码不能代替实际结果。修改前读取真实对象，保护手改；结果不明先查询已写对象，避免重复创建。

已在本地验证核心筛读、归档、恢复及版本保护的适用范围，完整原始证据留在本地维护档案。本仓库不宣称所有分支或环境都已通过。Windows 下部分受限沙箱可能使 PowerShell 初始化失败（`0xC0000142`）；该第三方问题仍需按实际环境处理。权限由使用者选择，安装脚本不自动放宽权限。
