# 阶段完成后等待用户命令

本约定适用于八阶段、十份业务 Skill，是启动、切换、返回与阶段收尾的统一规则。各阶段中的“交给”“进入”“分流”等表述仅说明材料去向；实际执行以本约定的启动条件为准。

本约定约束实际论文业务任务；组件设计、审查和维护按用户的维护请求进行，不因此启动阅读阶段或修改真实阅读状态。

## 启动与切换

用户明确调用目标 Skill，并明确下令开始该阶段后，才执行该阶段。调用可通过 Harness 原生技能入口或在消息中写明技能名；调用与开始命令可放在同一句，例如：“调用 paper-read-with-questions，开始第四阶段。”只调用但未给开始命令时，停留等待。

一次开始命令只授权对应阶段的本次任务。完成该阶段后结束本轮回应，等待用户下一条命令；“按整个流程做”、预先列出的后续计划不代替到达阶段边界后的新命令。用户可以决定跳过阶段、返回旧阶段或换论文，AI 保存其选择，不自行决定阅读深度、阶段顺序或是否归档。需要切换时，同样等待用户明确调用目标 Skill 并下令开始。

“明白了”“有兴趣”“继续”或用户补充想法，均不单独构成另一阶段的启动命令。目标不清时只澄清这一处。第六阶段的内容分类与写作范例是两份独立 Skill，分别启动、分别完成与等待。

## 当前阶段允许的工作

- 当前阶段内的追问、解释、核对资料、修改成果与继续讨论，沿用户实际请求进行；同一阶段中的图示、组件学习等内部步骤无需重新调用业务 Skill。
- 对齐读取与 paper-update-state 的日常保存是支持动作，可由当前阶段内部使用，完成后只返回当前阶段。独立调用它们时，完成本次读取或保存就停止等待。
- 已有原文、代码与工具可直接用于当前阶段核查；需要启动 02、04、05、06、07、08 等另一业务 Skill 时，先保存缺口和返回点，再等待用户调用及开始命令。资料核查也遵守此条件，不把它当作自动跨阶段的通道。
- 另一业务 Skill 的局部任务结束后，只返回结果与原任务的恢复入口并等待；恢复原阶段也由用户明确调用并下令。支持动作返回当前阶段不受此限制。
- 日常保存、暂停存档与第八阶段正式归档分别处理。用户说“中间存档”时保存当前正文、图、原话、疑问和位置，不自动调用 paper-archive。

## 收尾、续读与交接

当前阶段满足自身完成标准后，先完成既有保存及分项回读，简短说明“第几阶段／哪份 Skill 已完成”、本次成果、必要未完成项与实际保存结果，然后停止等待。未达到标准时说明待回应、待补、部分完成或用户选择提前结束，不把暂停或用户结束当作理解通过。

等待期间用户可以继续提出本阶段想法或修改需求；处理后重新保存、说明状态并等待。可提供下一阶段的名称和调用话术，但此时只准备交接，不执行其业务工作。

复用当前任务的“下一步”和相关过程正文保存当前阶段、完成／等待状态、待回答问题及恢复入口，不增加第二套状态文件。“下一步可做什么”是待选动作，不是已获授权的命令；新会话恢复、旧快照和历史授权都不能越过阶段等待。
