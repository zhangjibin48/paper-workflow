# 三笔记分别记录 Skill

本文件为已部署执行规则。执行前读取 [三笔记约定](../../三笔记约定.md)，依其来源、缺项、关联、保存与交接规则执行。

## 执行

1. 接续模式、目录、任务／论文、材料版本、本次深度与范围、04 已保存素材及最新适用规则。必要上下文由 [对齐 Skill](../../../01-对齐当前状态/Skill草稿/paper-align-state/SKILL.md) 取回；恢复时读取实际原话、笔记正文与待回答问题，已有判断直接沿用。
2. 读取已有三笔记及真实来源，按本次范围分别整理；只在有内容时创建对应草稿。主流程保持 04→05，一、二、三的内部处理不设固定过关顺序。用户只需一两份时不凑齐三份。
3. 一与三先取得用户已有判断，围绕必要缺项提问、据原文核查和整理；用户原话、作者声明、AI 候选分别标明。原文冲突保留依据，改变其个人结论须有真实表达，不编修正后的回应。无判断时可留待思考。
4. 二从实际原文、附录或代码提取本次需要的准确函数、公式、符号、模块与参数，保留版本及位置；未给出、未取得、冲突与推断分别记录。关联同文笔记一，不重复用途背景；一暂缺可先存二，按本次范围记录关联待补。
5. 需要原文定位／事实时交 [04 Skill](../../../04-原文定位＋提问式阅读/Skill草稿/paper-read-with-questions/SKILL.md) 做资料核查，携当前笔记条目和返回点；用户需要理解时借用局部陪读，结束后同样返回当前条目。新发现／补搜交 [02 Skill](../../../02-找论文并分层/Skill草稿/paper-find-screen/SKILL.md) 实际通过 Undermind MCP 检索。资料或工具不可用时报告真实缺口，不以记忆补事实。
6. 将原话、各自正文、受影响材料 ID／版本、依据、疑问和下一步交 [更新 Skill](../../../01-对齐当前状态/Skill草稿/paper-update-state/SKILL.md) 保存并回读。必要提问前先保存已有内容及问题，发出提问后结束本轮回应，等待真实消息；无回应不自动补一／三或认作已确认。
7. 更新既有笔记先读实际正文，只改受影响内容；有正式归档时对照实际正式对象、草稿和版本，保护用户修改，不直接覆盖 Zotero。保存分项报告，正文、索引或必要笔记失败时保留成功对象和待办；01、08 的既有规范不作扩充。
8. 按本次用途交后续阶段：内容归类交 [06 分类 Skill](../../../06-分类，积累写作范例/Skill草稿/paper-classify-content/SKILL.md)，实际写法素材交 [06 范例 Skill](../../../06-分类，积累写作范例/Skill草稿/paper-collect-writing-examples/SKILL.md)，实际原句及语境线索交 [07 Skill](../../../07-留一句写作参考/Skill草稿/paper-keep-writing-reference/SKILL.md)，只按需要选择；未部署／不可用时只准备材料。正式归档仍固定源版本和快照，携适用笔记及二→一关系交 [08 Skill](../../../08-归档与关系图/Skill草稿/paper-archive/SKILL.md)，依真实回执更新归档标记。暂停保存正文、待回答问题和恢复入口。

## 完成与停留

本次适用笔记有独立正文，来源、未知项及关联清楚，实际正文和索引回读成功时，才报告对应内容已整理并保存。用户判断待形成、证据待核查、本次不适用与保存失败分别说明；已落盘不等于结论已证实，已整理不等于正式归档，不以三份齐全作为统一完成门槛。
