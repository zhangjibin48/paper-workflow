# 05 的三笔记整理、核查与交接约定

供 [paper-record-three-notes](Skill草稿/paper-record-three-notes/SKILL.md) 执行时读取。本文件为已部署执行规则。正式三笔记结构与归档边界继续以 [08 归档约定](../08-归档与关系图/归档约定.md) 为准；工作区写入复用 [01 状态约定](../01-对齐当前状态/状态约定.md) 和 [临时成果约定](../01-对齐当前状态/临时成果约定.md)。本轮不修改 01 或 08。

## 一、进入、范围与已有材料

1. 使用已有运行模式、状态目录、任务／文献标识、材料版本、深度与本次目的、工作区索引及适用规则。设计审阅只读样稿；试跑用隔离副本；正式运行使用已指定位置，不把组件样稿当真实记录。
2. 接收 04 的已保存原话、阅读正文、技术素材、真实原文位置、未解问题及理解依据。用户直接提供笔记或论文时也可进入，必要上下文由现有对齐 Skill 取得，不虚构已完成上游流程。
3. 取回实际三笔记草稿、原话和相关来源，明确哪些属于本次范围。筛读可以没有三笔记；本次只整理二时一、三不必成形。缺少本次必要资料记待补，确实不适用的内容无需创建占位文件。
4. 独立进入也加载最新适用行为规则，已有判断直接承接。长期纠正按 [行为规则约定](../01-对齐当前状态/行为规则约定.md) 交既有更新 Skill 保存，临时要求按相关任务／论文范围处理。

入口核对完成时，应能定位当前论文／材料版本、已有笔记、本次范围和必要缺项；无需用户重填背景或另做一轮复述。

## 二、先分清来源，再组织文字

| 来源 | 保存与使用方式 |
|---|---|
| 用户原话／真实复述 | 保留原句及原话 ID、任务／文献、时间与实际可用对话定位；无消息 ID 就注明未取得。AI 整理与原句分别保存 |
| 用户判断的整理稿 | 一、三的个人结论须能回到用户真实表达。可整理清楚已有意思；新增判断、改变原意或影响结论的歧义需取得其表达，不能靠用户未反对推定认可 |
| 作者贡献声明／自述限制 | 保留出处和作者主张身份，不自动成为用户认同的创新／不足，也不单独证明领域首创或普遍优越 |
| 原文／附录／代码事实 | 按实际读取版本核对，进入二或作为一／三的依据；每项关键技术信息可定位，证据不足明确保留 |
| AI 候选与推断 | 清楚标为 AI 来源及待核查，不写成用户第一人称。用户要求建议时可提供；之后若形成其本人判断，记录新的真实表达和来由，保留原候选来源 |

一段材料可支持多份笔记，来源引用复用。记录“用户怎样理解”“作者怎样说”“原文支持到哪里”三个不同问题，不把 AI 讲过视为用户已掌握或同意。

隔离试跑中的控制指令、虚构角色发言和真实人类回应，沿用已有来源身份分别引用：调度指令记为测试控制，虚构发言记为夹具，只有实际人类回应记为真实用户表达。

## 三、笔记一：方法创新

核心内容为用户对创新的理解、可能用途、认为能优化哪些参数或对象、已有依据与未验证部分。依据可来自具体机制、结构组合、实验结果或对比材料，按实际取得情况记录。

- 优先取回用户在 04 或已有笔记中的判断，直接整理；不足以支持本次记录时再问一个当前有用的问题，例如“你认为这里值得借用的创新体现在哪里，依据是哪一部分？”用途、参数没有想好可保留未知，不要求填满栏目。
- 作者贡献声明可作为核查线索。只有单篇材料时，不将其改写成领域普遍首创；要确认前作对比而缺资料时保留待查，必要新找文交 02 实际搜索。
- 用户的应用或优化设想保持设想身份。优化对象／参数有影响结论的歧义时再澄清，不将尚未验证的船舶用途写成论文已验证应用。
- 原文与用户理解不符时保存原话，指出支持与冲突的位置；解释或回读后等待真实反馈，不能替用户编出修正后的个人结论。

## 四、笔记二：具体方法

按本次已读范围中的模块或实际信息流组织，准确保留所需函数、公式和参数；技术细节深度随用途决定，准备借用／复现时再补所需代码与配置。

| 技术项 | 至少需要说明的内容 |
|---|---|
| 模块／函数 | 做什么、输入输出、上下游关系；代码函数名与位置只在实际取得代码时填，不从论文术语猜名称 |
| 公式 | 准确表达、符号意义及原文给定的条件／维度，真实章节／公式等位置；关键 OCR 或符号不可靠时先取得可核实资料 |
| 参数／配置 | 原文或配置给出的准确值、适用设置、实际版本与出处。没有给出或当前没取得则如实标明 |
| 训练／推理与实验条件 | 相关时区分二者，标签、损失与预测输入不混用；仅保留本次范围必要的真实事实 |
| 证据与差异 | 论文／附录／代码版本及位置，哪些已核对、哪些存在冲突、哪些只是 AI 推断 |

“来源未给出”“当前未取得”“版本冲突”和“AI 推断”分别表达。版本冲突先保留各自值和适用语境，不静默选择一个，也不把推断填成作者设置。抽取文本、远端工具回答与当前模型看过原页图的证据类型如实区分。

笔记二关联同一论文的笔记一，不重复其用途背景：

- 一存在时用实际稳定材料 ID／路径关联；正式 note key 只由实际归档结果提供。
- 一暂缺时二可先保存，关联记待补；不创建空的一、不编造链接或 key。
- 一本次不在范围时，未来关联作为后续事项，不妨碍二在本次范围的完成。
- 一本次必要却保存失败时，一及关联保留未完成，整体部分完成；二已成功的部分继续保留。

有多个创新条目且对应关系确有用途时，可标明技术条目支持哪个已有判断；不强制为每个公式虚构一个创新点。未运行代码／实验时不称已复现或已验证算力可行。

## 五、笔记三：方法不足

先沿用用户已有不足判断或疑问；必要时围绕其所读内容提问，例如“你对哪些条件或结果仍有疑问，依据在哪里？”保留用户先思考的空间，不先给一套不足再让其附和。

记录实际判断、依据、适用范围和核查结果。验证覆盖缺口、用户疑问和已证明的方法问题分别表述：

- 当前材料没有验证某工况，最多说明该材料的验证范围，不自动证明方法在该工况失败，也不保证整篇未读取部分没有相关实验。
- 作者自述限制、AI 候选可作为单独标明来源的材料，不能代替用户判断来宣称笔记三已完成；尚无判断时可以只保留来源素材和待思考入口。
- 核查发现判断过强时保留原话与真实依据，帮助用户修正；未得到反馈前保持待核查／待确认，不改成其已认同的新结论。

## 六、内部顺序与必要等待

1. **汇集并分流**：读取实际资料、已有笔记和相关原话，按来源及职责组织。已有清楚判断直接整理，技术事实回到实际出处；暂不能归属的内容先作为素材保留。
2. **处理可完成部分**：分别整理一、二、三的已有内容。二的事实充分就可先处理，不以一或三先成形为前置条件，不要求按一→二→三逐份过关。
3. **针对必要缺项提问／核查**：只问会影响当前笔记的缺项，已有原话不重复询问。原文定位／事实核对交 04 资料核查，用户确需理解时借用局部陪读；按 [04 调用约定](../04-原文定位＋提问式阅读/阅读与提问约定.md) 携当前笔记条目与返回动作，处理后回到该条目，不重新启动三笔记整理。新文献发现交 02，通过真实 Undermind MCP 检索。
4. **先保存再等待**：将已有原话、笔记正文及实际待回答问题交更新 Skill 保存并回读，再向用户提出问题并结束本轮回应。无新内容的重复等待不制造版本；没有回应时不编个人判断或假定已同意。
5. **据真实回应更新**：保存新原话，只更新受影响条目及版本；核对原意、依据、未知项和二→一关联。新增讲解不自动增加掌握范围。
6. **分别交接**：保存结果分笔记说明，后续按本次用途进入 06／07／08；用户暂停时保留正文、问题和恢复入口，不强制正式归档。

没有判断的笔记保持未形成，不为记录“待思考”而创建空笔记；待办记入既有任务下一步／索引说明，索引不指向不存在的正文。用户明确暂停不要求先回答当前问题。

## 七、三份正文与保存

继续使用既有工作区：

```text
状态目录/任务成果/<任务标识>/文献/<文献标识>/
  笔记一草稿.md
  笔记二草稿.md
  笔记三草稿.md
```

已有路径直接沿用，只在有真实内容时建立对应文件。每份实际笔记至少保留：

- 独立材料 ID、任务／文献、版本、日期、来源附件身份与版本；本次整理的实际资料范围。
- 该笔记自己的正文、对应原话 ID／原文位置、判断或事实的来源、待核查部分。
- 二对应一的实际材料引用或关联待补；一／三不被迫依赖二存在。
- 实际正文及索引回读结果，归档映射、已归档版本与当前待归档版本按既有规则另记。

05 只向现有更新 Skill 交增量：运行模式、状态目录、事件（成果暂存／重要进展／收尾等）、任务／文献、受影响材料、已读取版本、原话和实际正文／路径、材料 ID／版本、字段依据、疑问及下一步。01 不增加字段，05 不直接写共享工作区。

更新 Skill 写前重读，先原话及正文回读，再索引，最后更新当前任务入口；实际成功才报告已保存。多份笔记或正文／索引部分失败时逐项说明，保留成功项及可恢复路径；不能以“已有草稿”摘要或工具成功提示替代正文。

## 八、更新既有笔记与正式归档

修改前读取真实内容、材料版本和未完成项，保留用户已有内容。只改用途时不重写技术方法与不足；同一增量不重复追加，无变化不制造新版本。切换任务／论文由现有更新 Skill 先保护原材料再切换。

涉及已有正式笔记时，按实际可用读取工具及 08 映射对照 Zotero 正文、现有草稿和归档版本，保护用户手改与未归档增量。无法读到必要正式正文时说明缺口，先保存可定位的修改建议，不用空白或旧草稿覆盖实际对象。过程草稿不成为第二套独立编辑的正式笔记库。

05 不直接写 Zotero／Obsidian，正式归档交 08：

- 向更新 Skill 提交本次适用材料，固定提交快照并回读，再交 08 源材料 ID／确切版本、快照、来源、二→一关系和必要缺项。
- 08 逐项写入并回读，返回各独立 note key 和源版本映射；正式三笔记以 Zotero 为主，Obsidian 保留入口。
- 一或其他必要项失败时保留部分结果，不重建已有成功笔记；旧版成功只对应旧版，后来新增或修改的版本仍待归档。

本节复用已有 08 规则，不改变其对象映射或执行接口。06 两份独立 Skill 与 07 参考句 Skill 均已有草稿，按本次需要交接；未部署／不可用时只准备材料，不声称已调用。用于写作的真实原句单独保留原文、语境与位置，AI 改写的笔记不当引用。

## 九、完成与停留

本次范围内有实际内容的笔记各自独立、来源和待核查项清楚、二→一关系或待补原因明确，正文及索引已回读，才可报告相应笔记已整理并保存。

缺少本次必要判断或证据时说明待思考／待核查，必要保存失败时说明部分成功；不适用的笔记不造成虚假失败。可以结束本次会话并保留必要未完成项，不能为结束会话代填个人结论。

分别说明“已整理什么、原文核对到哪里、实际保存什么、是否已正式归档”。尚待核查的内容即使已落盘，也不能称结论已证实；笔记成形不自动证明用户已掌握。
