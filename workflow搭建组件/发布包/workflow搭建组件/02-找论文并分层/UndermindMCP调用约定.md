# 02 的 Undermind MCP 调用约定

2026-10-27。用户明确要求：02 找文时让 AI 实际调用 Undermind MCP，不能只依据模型自身知识列论文。当前为未部署设计；本轮仅核对公开官方文档，未连接用户账户或发起文献检索。

## 1. 必须达到的结果

- 新找文或补搜必须通过 Undermind MCP 的文献检索工具取得实际返回；模型知识用于理解需求、组织查询和解释，不能冒充本轮检索来源。
- 检索范围按任务选择：全局文献、种子论文的参考文献、引文，或深度检索。引用链本身是有效找文；满足本次目标并有可追溯返回时可以独立完成，不追加全局搜索或深搜作为必过条件。
- `get_orientation`、列工作区、元数据核对和普通网页浏览均不能单独证明完成了新文献检索。新检索需要实际搜索调用及其结果。
- 连接、授权、工具或结果不可用时，保存真实状态并报告检索尚未完成。Zotero 和原始网页可提供已有资料或事实核对，不静默替换用户指定的发现通道。
- 恢复旧检索使用其原工作区和服务返回标识查询，不能用模型记忆重建结果，也不能因为没有立刻拿到结果就重复启动深度检索。

## 2. 官方已公开的工具与本阶段用法

以下工具名和功能核对自 [Undermind 官方 MCP 页面](https://www.undermind.ai/mcp)。这是公开功能说明，不是已取得真实账号的完整参数 schema。调用时以连接后实际暴露的工具和参数定义为准；客户端名称前缀按实际映射，不自行拼造工具。

| 官方工具名 | 官方说明对应的能力 | 02 如何使用 |
|---|---|---|
| `get_orientation` | 获取 Undermind 使用指导 | 首次接入或需要更新工具用法时读取 |
| `list_workspaces` | 列出可访问工作区并识别连接账户 | 使用已配置工作区；目标缺失或确实有歧义时才补充 |
| `search_papers` | 查询全局文献、工作区文献或某篇论文的参考文献／引文，支持若干筛选项 | 按目标选全局、参考文献或引文；保存实际范围和种子，符合任务的引用链检索可独立完成。工作区限定搜索不能冒称覆盖外部全局或指定引用链 |
| `launch_deep_search` | 从开放研究目标启动深度文献搜索，返回排序论文和综合结果 | 方向探索、方法发展或需要较完整覆盖的问题；保留其实际任务标识和返回状态 |
| `inspect_deep_searches` | 查看已有深度检索及排名、评分和摘要 | 读取历史结果、核对可能已经提交的任务；具体选择／查询参数由实际 schema 决定 |
| `display_deep_search_results` | 展示运行中的进度或完成后的排序结果 | 按实际可用返回取得进度和结果；图卡不是前提，文本和链接也要能交接 |
| `lookup_papers_by_metadata` | 按题名、DOI 或参考文献批量识别论文 | 指定候选／种子的身份核对和版本对应；单纯识别元数据不代替任务所需的文献发现检索 |
| `get_paper_info` | 获取论文元数据、引用信息、PDF 可用性及工作区位置 | 补充候选身份与可取得资料范围 |
| `read_pdfs` | 针对论文全文回答问题，可涉及图表公式 | 有明确筛选疑问且全文可用时使用，结果按可核查程度记录；不等于本机模型已经看过原页 |

连接地址为 `https://mcp.undermind.ai/mcp`；官方使用 Streamable HTTP 与 OAuth PKCE，需 CIMD 或预注册客户端身份，见 [集成参考](https://www.undermind.ai/mcp/reference)。本机 Harness 的授权适配仍沿用既有接入设计，部署时另验，不在本轮修改配置。

## 3. 执行前检查

1. 区分设计审阅、隔离模拟和正式运行。审阅样稿不发起真实搜索；模拟工具结果只用于验收，不能作为真实检索来源。
2. 正式执行读取实际 MCP 工具目录及 schema，确认连接账户和目标工作区。预先已给出的信息直接沿用，不要求用户重复配置。
3. 如果当前没有 Undermind MCP 或必要搜索工具不可用，返回“未连接／工具不可用／待授权”等真实原因。不能改为列出 AI 熟悉的论文并标记检索完成。
4. 已有查询意图、任务标识或未完成调用时先查记录；本轮查询、范围和筛选条件应明确，避免不经判断就重复发起相同任务。

官方工具名不保证任何客户端都原样暴露所有工具；部署发现名称／schema 有变化时核对映射后修订本约定，不能猜参数。工作区、账号标识和调用记录不包含 OAuth 凭据。

## 4. 三条执行分支

### 新检索／补搜

1. 从 01 接收目标、基础、约束和相关规则，查已有线索用于组织问题与去重。
2. 形成目标、范围和选用理由；引用链先核对种子论文身份／版本并明确方向。由更新 Skill 保存意图和本地检索标识。
3. 按下表实际调用 `search_papers` 的相应范围或 `launch_deep_search`。参数按真实 schema；本约定中的方向、路径等是工作流记录字段，不假定就是服务参数名。
4. 获取返回，立即保存调用、实际范围、结果、状态和可恢复信息；引用链另保存种子及路径。运行中或约定范围仍有未读取的后续结果时记录待续，不能冒称取全。
5. 依据真实返回建立候选，关联哪次调用、哪份结果及哪条链路；核对身份、必要原始来源和选文字段，再按本次用途分层。

| 任务目标 | 合适的搜索路径 | 完成范围怎样表述 |
|---|---|---|
| 开放问题、跨方向候选或较广范围查找 | 全局范围 `search_papers`，或按需要 `launch_deep_search` | 对实际查询、过滤条件及已返回范围作判断 |
| 给定论文查前作、方法来源或相关基础 | `search_papers` 的参考文献范围 | 指明种子和已检查的参考文献范围；前作及方法来源作为待核对候选 |
| 给定论文查后续工作或改进候选 | `search_papers` 的引文范围 | 指明种子和已检查的引用它的论文；具体改进关系另按原文核实 |
| 围绕架构发展继续追踪多跳引用链 | 按每一步目的选择参考文献／引文范围 | 保存每跳种子、方向、调用与返回，说明实际追踪边界，不声称覆盖整个领域 |

参考文献用于找可能的前作，引文用于找可能的后续研究，两者都不是方法继承／改进的直接证据。仅有引用、发表先后或相似名称时保留候选，具体方法关系核对原文或代码后再确认。

完成本次约定的引用链检索并保存结果后，可以直接进入筛选和 03，不必再全局搜索。扩大范围应有目标变化或明确缺口作为理由；引用链真实无结果也可结束本轮尝试，不靠追加全局搜索来凑完成状态。快速、深度和引用链检索按问题选择；首轮展示数量不代表服务任务规模或穷尽文献。

### 恢复检索

1. 从已保存记录取回原工作区、查询目标和服务返回标识。
2. 通过实际可用的历史／进度／结果工具读取原任务；官方公开了 `inspect_deep_searches` 和 `display_deep_search_results`，具体查询方式以 schema 为准。
3. 返回仍在运行时按服务提示或有间隔的续接方式处理，保存检查时间与下一步；相同状态不密集重复查询。
4. 返回结果后续接原候选和评估，不重新随机分配文献身份。找不到任务或身份不确定时报告缺口，不编造 ID 或盲目重发。

快速检索若没有远端任务 ID，使用已持久保存的真实调用与结果继续筛选，明确标注原查询时间；需要刷新或补搜时创建新调用批次并实际搜索。不能把没有服务任务 ID 一律当作记录丢失，也不能把旧结果宣称为刚执行的新搜索。

### 指定候选核对

用户只要求核对已提供论文身份时，可调用 `lookup_papers_by_metadata`、`get_paper_info`，记录原始来源。若要求查该论文的前作或后续研究，则进入上面的参考文献／引文搜索分支；这是有效发现检索，不属于单纯元数据核对，也不要求转成全局搜索。

已有定位明确、只需要解释或阅读的论文，可以由调用方直接进入 03／04；这属于跳过 02，不是 02 已执行外部搜索。

## 5. 什么才是调用证据

检索记录必须能关联真实 MCP 工具调用与返回；Agent 写下“已调用”或把状态改成完成，均不单独构成证据。

| 记录项 | 要保留的真实内容 |
|---|---|
| 本地检索标识、调用批次 | 区分新问题、重试、补搜与恢复；本地标识不能假装是服务 ID |
| 服务与范围 | 实际 MCP 服务映射、账户／工作区引用、任务要求的范围、实际全局／工作区／参考文献／引文等范围及选择理由 |
| 引用链入口与路径 | 种子论文真实标识及版本，参考文献／引文方向；每跳从哪个种子、经哪次调用发现哪个候选，及已检查／未完成的边界 |
| 调用与查询 | 实际工具名、按真实 schema 提交的业务参数、调用时间与返回时间 |
| 执行引用 | Harness 提供的调用／事件 ID（如可得），及真实工具返回内容或持久保存位置；未暴露的 ID 明确未知，不能虚构 |
| 服务任务／结果标识 | 仅保存服务实际返回值，未返回时记未取得；远端结果链接同样取自返回 |
| 返回状态与错误 | 请求未提交、提交结果不明、运行中、成功返回、失败、无结果等真实情况 |
| 候选来源绑定 | 每个新发现候选对应的搜索记录、工具结果中的论文标识／DOI／链接和证据位置 |
| 本地保存结果 | 由更新 Skill 回读确认的实际路径与版本，不能把外部返回成功当成本地已保存 |

建议保存位置：

```text
状态目录/任务成果/<任务标识>/
  检索记录/<检索标识>.md
  检索记录/返回记录/<检索标识>/<调用批次>.json
  文献/<文献标识>/选文记录/<评估标识>.md
```

返回记录保存必要请求业务参数和工具返回，检索记录保存可读概览和指向它的引用；评估只保存来源绑定和选文判断，不再复制一套可编辑的搜索结果。全部由更新 Skill 写入，02 只提供真实增量。

原始线索来源和 MCP 获取／核对方式分别记录。候选区分 Undermind 本轮发现、历史搜索、用户提供、Zotero 已有、模型线索经 MCP 核对；后者不能改标为本轮搜索新发现。模型想到的题名在取得真实检索／核对证据前，只能作为待检索线索。

## 6. 中断与失败

- **连接／授权失败**：记录真实原因和待处理项，外部检索未完成；可以保留用户已有材料，但不能声称这些来自本轮 Undermind 搜索。
- **提交超时且结果不明**：保留意图和错误，先用现有历史工具寻找可匹配任务；匹配不唯一或仍不确定时说明情况，不立即重发深搜。
- **远端任务已返回但本地保存失败**：报告远端真实标识与未保存部分，优先补存，不启动第二份搜索；不能保证没有持久标识的任务下次一定可恢复。
- **已取回部分结果**：可以注明范围做初步判断，但仍记录未完成部分，不标整轮检索完成。
- **真实返回无结果**：保留实际查询和无结果返回；下一步可以调整条件，但不会自动拿模型记忆补出论文。
- **暂停**：调用更新 Skill 保存执行记录、源材料与下一次读取入口，保留远端任务；不自动删除或重建远端搜索。

## 7. 完成与验收

找文完成按任务与范围判断：有真实搜索调用、已取得所约定范围的结果或明确无结果、候选与返回及引用链对应、选文字段有依据或明确未知、检索与评估已本地保存并回读。全局、参考文献、引文和深搜均可作为有效搜索路径；满足目标的引用链可以独立完成，不能因没有全局或深搜调用而判失败。

“引用链找文完成”与“改进关系已确认”分别记录。若仍缺原文依据，论文可以作为后续改进候选供进一步阅读，但不能声称已证明改进；需要确认关系的任务应保留相应待核查项。只有请求已发出、仅查看帮助或只有模型生成清单，都不满足真实检索要求。

隔离模拟检查决策；真实联调还须从 Harness 执行记录确认调用发生、参数和返回匹配，并抽查候选来源。格式检查、官方页面阅读和模拟样稿都不能代替该联调。
