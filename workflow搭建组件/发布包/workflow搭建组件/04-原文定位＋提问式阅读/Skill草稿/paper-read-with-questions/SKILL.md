# 代码流程图与论文图文陪读 Skill

执行前读取 [阶段控制约定](../../../../阶段控制约定.md) 和 [阅读与提问约定](../../阅读与提问约定.md)。制作或更新代码图时读取 [Drawio 制图约定](../../Drawio制图约定.md)。

## 执行

1. 核对用户对本 Skill 的明确调用及开始命令，接续任务、论文／附件版本、代码仓库与版本、已有图和理解记录、最新适用规则。必要读取和保存复用 01；恢复从实际正文和图接续，不根据摘要重建。
2. 主流程先读取实验代码的实际入口、配置、模型与调用路径，制作并展示 draw.io 的完整流程图。有训练和推理时分别画图，连接共享模块及权重；标出论文核心创新所在节点。代码或关键路径缺失时保留缺口，先补图所需材料，不以论文示意图冒充代码全流程。
3. 图已核对并可供用户查看后，以图为导航，按“整体 → 各大组件 → 组件内部组成、关键参数与公式 → 整体串联”学习。逐层对应真实代码符号、论文位置及输入输出；按需展开子图。影响代码理解或核心创新的细节讲清，其余琐碎细节可暂留。
4. 每轮结合图定位、必要解释和当前主要问题推进。需要用户思考时，先把本轮正文、图版本、问题与下一步交更新 Skill 保存回读，再发出问题并结束本轮，等待真实回应。收到追问先回应；已有有效理解直接复用，不机械逐行测验。
5. 根据真实回应纠偏，逐项核实核心创新点的目的、机制、公式与实现对应，以及它对整体实验流程的作用。AI 已讲解、用户有依据的理解和纠正待确认分开记录；跳过复述或提前结束时保留未验证范围。
6. 用户明确启动的局部资料核查只取得原问题所需的真实证据、位置、版本和支持范围，保存结果及返回点后停止等待，不重画无关全图或开展整套陪读。需要另一业务 Skill 时只准备交接，等待用户明确调用并下令。
7. 整体、组件、关键参数和全部核心创新点达到约定的理解标准且相关成果已保存后，明确报告“第四阶段已完成”，停止等待。用户可继续讨论、要求中间存档，或自行调用下一阶段并下令开始；三笔记和正式归档不自动执行。

## 完成与停留

代码全流程图与实际版本对应，训练／推理按实际分开，整体与组件关系、关键公式和参数清楚；每项核心创新都有真实用户回应支持理解，关键偏差已得到反馈确认，正文、图与索引已回读，才报告第四阶段完成。

缺代码、图未可读、核心创新待理解、纠正待确认、用户暂停和保存失败分别说明。局部核查按原问题判断结果，不增加掌握记录。阶段结束、理解完成、本地存档与正式归档继续分开判断。
