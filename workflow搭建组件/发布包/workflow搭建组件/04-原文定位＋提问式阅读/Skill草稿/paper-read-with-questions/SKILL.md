# 原文定位＋提问式阅读 Skill

本文件为已部署执行规则。执行前读取 [阅读与提问约定](../../阅读与提问约定.md)，按其证据、等待、记录及交接规则运行。

## 执行

1. 接续本次目的、任务／论文、材料版本、相关原话和最新适用规则，按约定识别陪读或资料核查；其他阶段调用时保留原待办及返回点，无需用户选择内部模式。沿用 03 已确认内容；必要上下文由 [对齐 Skill](../../../01-对齐当前状态/Skill草稿/paper-align-state/SKILL.md) 取回。续读恢复实际正文及原用途／待办。
2. 陪读时先整体框架，再沿真实信息流读关键模块，按需深入，最后整体串联；已有主线或指定局部问题直接接续，分支与循环按原文结构。资料核查只取完成原待办所需范围，不进入陪读提问循环。
3. 读取实际原文及必要语境，核对附件身份、版本和位置。只有摘要就限定范围；关键图或公式不可读时保留待补，不编造细节、页码或已看图经历。新找文交 [02 Skill](../../../02-找论文并分层/Skill草稿/paper-find-screen/SKILL.md) 实际使用 Undermind MCP。
4. 资料核查取得结果后，将真实摘录／事实、位置、版本、必要语境、支持范围与缺项交 [更新 Skill](../../../01-对齐当前状态/Skill草稿/paper-update-state/SKILL.md) 保存回读，并返回原任务及待办，到此结束；不要求用户复述或默认交 05。陪读则给出定位、阅读任务及主要问题，先保存再发出任务并结束本轮，等待真实回应。
5. 收到真实回应后，对照原文指出有依据的理解和关键偏差，按需补背景、解释或追问；清楚时继续下一部分，次要疑问可暂留。用户主动求助可以直接解释，明确跳过复述时保存其要求与未验证范围。AI 已讲解、纠正待确认和用户实际理解分别记录。
6. 将原话、解释与纠正、理解依据、疑问、材料 ID／版本及下一步增量交更新 Skill；再次等待前先保存。复用 01 现有通用保存机制，01 不作补充或修改；依据实际正文、索引和入口回读结果分别报告，失败不冒充已保存。
7. 陪读按目标串联或保留真实暂停／待补状态。其他阶段借用的局部陪读在该问题结束后返回原任务；只有主流程阅读结束且需要整理三笔记时，才交 [05 Skill](../../../05-三笔记分别记录/Skill草稿/paper-record-three-notes/SKILL.md)。阅读中暂存自然素材，个人判断由用户先提出；暂停只保存，不继续分流。下游未部署／不可用时只准备交接，归档仍交 08。

## 完成与停留

资料核查按原待办返回实际证据、定位、版本、支持范围、缺项和保存结果，完成与否依原问题判断；证据不足返回待补，不增加用户掌握记录。其后由原任务继续。

用户实际复述或明确确认支持的理解范围、未解问题、原文定位与已保存版本清楚，才可报告本次理解进展。理解目标完成还须有用户回应支持关键偏差已修正；影响主线的误解仍在时继续纠偏或按用户选择暂停／调整范围。按目的说明已完成范围与下一步，无需全部细节弄懂。未回应停在待回应，AI 纠正后未得到反馈停在纠正待确认；资料缺失、用户暂停与保存失败分别记录。会话结束、阅读完成和正式归档完成继续分开判断。
