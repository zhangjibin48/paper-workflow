# 04 的 draw.io 中文横向制图约定

制作或更新 04 代码图时读取本约定，并实际查看 [标准示例与错误对照](制图示例/示例说明.md) 指向的图像。默认工具为 draw.io；使用其原生节点、文字、分组和连接器，交付可编辑 `.drawio` 及逐页可读预览。用户本次另有明确指定时按其要求处理，记录工具与交付格式。

图的视觉语言参照 Transformer 经典论文架构配图：白底、低饱和浅色填充、黑色轮廓与箭头、圆角模块、嵌套组件和重复标记。整体改为中文、横向从左到右。示例帮助选择样式和布线，不提供目标论文的事实；目标结构始终从实际代码确定。学习、保存与阶段等待见 [阅读与提问约定](阅读与提问约定.md)。

## 先确定实际流程与分图

核对论文／附件、仓库来源与实际版本，按实验命令、入口、配置解析与覆盖、数据构造、模型构造及调用追踪启用路径。每个实质节点可回到文件／类／函数及必要论文位置，映射保存在阅读记录；图面保留简短名称和必要参数。

- 主图与必要子图共同覆盖选定实验从入口到结果的全程；关键分支、循环、数据形状及核心创新所在节点清楚。辅助代码可合并为职责明确的节点。
- 有训练和推理时分别画，关联共享模块及权重保存／加载；存在独立评估、规划或环境交互时按真实调用表达。训练核对数据、计算、损失、梯度、更新、验证与保存等适用环节；推理核对加载、输入处理、计算及输出／评估。各流程仅出现其实际使用的输入与操作。
- 可按模型架构、训练、推理／规划和组件内部拆图，图数随实现决定。样图的三页、五部件、网络数量、参数值和强化学习机制均只属于示例。
- 明确区分数据流、梯度流与参数更新；确需同图表达时标注类型。重复出现的模型说明参数是否共享；跨页使用稳定节点标识或明确引用。
- 核心创新用清楚名称、边界或简短标记识别，并记录“论文主张 → 图节点 → 实现”。作者主张与用户自己的创新评价分别保留。

代码、入口或核心实现缺失时保留已证实路径及具体缺口，停在补资料／核图；静态推导与实际运行结果分别记录。完整覆盖指选定实验及配置，不要求画仓库每个工具或每行语句。

## 中文、版式与样式

主输入通常在左、输出在右，主要计算从左到右；并行分支上下对齐，反馈沿外围返回。外层圆角框表达组件范围，内部小圆角框表达具体计算。复杂结构展开为能回到主图的子图，保持可读字号和适当画布比例。

模块、注释和图注以中文表达；必要的模型专名、数值和公式符号可保留，变量首次出现时解释。源码英文符号在图外映射中保留。拼接、相加、归一化和停止梯度等操作准确命名，简化文字仍应保留机制含义。

同层模块的尺寸、间距、边框、字体和箭头样式统一。支持中文的统一字体分出标题／模块／注释层次，文字与边框留足内边距；长解释和来源清单放阅读记录。重复标记如“2×”“N×”贴近其真实边界，明确串行层、时间步、优化迭代或并行集合，不能混用含义。

初始样式可沿用示例：黑色线约 3–4 个图形单位、中文模块字约 23–27 个图形单位，随画布与导出比例整体调整；数值不是固定验收阈值。建议配色如下，同图同层相同作用保持一致，必要时加简短图例；颜色不能代替文字与连线。

| 浅色 | 色值 |
|---|---|
| 粉 | `#F3E2E2` |
| 蓝 | `#CDE7F3` |
| 黄 | `#F3F2C6` |
| 橙 | `#F7E2BD` |
| 绿 | `#D4E6D0` |
| 紫 | `#DEDEEC` |
| 分组灰 | `#F4F4F4` |

## 端口与布线：必须逐处检查

1. 由模块几何确定端口，按实际分支连接点计算主干范围。主干准确止于首末连接点，**没有越过连接点的突出短尾**；确需继续的外部输入／输出接明确来源／去向。
2. 连线从实际模块端口／连接点出发，连续连接到实际目标。外层框仅表示范围时，穿过其边界后继续接到内部模块；不能停在外框留下内部断线。
3. 分支用清楚的 T 形连接，真实交汇用一致连接点；无连接关系的交叉优先改道，保留交叉时表达为不相连。几何相交不改变独立输入的含义。
4. 优先水平／垂直线段及圆角转弯，绕开无关模块、文字、标题和注释。箭头准确落在需要表达方向的终点；转弯处不留悬空箭头，汇流主干可用无箭头线段。
5. 同一路径绘制一次，避免重复线段、局部异常加粗和重复箭头。短连线的长度、箭头大小与相邻模块间距匹配，箭头不压住前一模块或文字。
6. 布局修改后重算受影响端口、主干和途经点，检查所有共用该布局的图页。单纯缩短线头不能代替检查连接是否仍完整。

可对照 [连线正误图](制图示例/连线正误.png) 检查突出短尾、内部断线与独立输入误连。错误图仅用于识别问题，复制样式时采用其中的正确一侧。

## 制作、导出与交付

1. 先列节点与真实连接关系，再安排主图／子图及横向布局，最后按模块和端口坐标绘制。既有图写前读取，保留手改、无关页及布局，只修改受影响部分。
2. 发现实际 draw.io 工具、桌面应用或 CLI，读取真实帮助／schema 后操作。没有专用 Skill 时，可生成未压缩的 `mxfile / diagram / mxGraphModel` XML，再交真实 draw.io 打开或导出；正确转义文字和属性。
3. 保留原生可编辑节点、文字和连接器，分组能表达组件关系；按目标端口绑定连接。图像附件可辅助说明，整张位图嵌入空白画布不算可编辑流程图。
4. 核对 ID 唯一、连接端点有效、节点与边归属正确。图页／画布范围包住实际对象，清除无意的越界对象；极小越界也可能使导出多出整页空白。
5. 为实际使用的每一页导出 PNG 或 SVG，并**逐页实际查看**。先看整体，再放大首末分支、交叉、短箭头、转弯和组件边界；检查文字、遮挡、裁切、断线、线头及方向。修正源文件后重新导出和查看受影响页。
6. 展示源图入口与可直接查看的预览。交现有更新 Skill 保存持久源文件、各页预览、代码／论文版本和节点映射；必要生成代码一并保存。由它按既有正文／附件、索引、当前入口顺序回读。

XML 结构检查、代码语义核对和视觉检查分别记录，三者均通过且已保存回读才报告图已完成。导出失败或还没查看时说明“源图已生成、展示待核对”；工具不可用时保存缺口，等待修复或用户指定替代工具，不把其他图法静默算作 draw.io 完成。图已完成不增加用户已理解或已复现实验的记录。
