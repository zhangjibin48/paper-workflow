# 04 的代码流程图、图文学习与阶段完成约定

供 [paper-read-with-questions](Skill草稿/paper-read-with-questions/SKILL.md) 执行时读取。阶段启动与等待以 [阶段控制约定](../../阶段控制约定.md) 为准；共享保存复用 [状态约定](../01-对齐当前状态/状态约定.md) 和 [临时成果约定](../01-对齐当前状态/临时成果约定.md)。

## 一、进入与恢复

1. 用户明确调用本 Skill 并下令开始后，使用已有任务、状态目录、论文及附件身份／版本、代码定位、本次目的、工作区索引与最新适用规则。设计审阅读组件，试跑用隔离副本，实际阅读使用指定正式位置。
2. 主流程默认是基于实验代码的图文学习。直接提供论文和代码也可进入，不补造 02／03 经历；03 的解释、已确认主线、用户疑问和类比纠正直接沿用。
3. 核对代码与论文的对应关系：仓库来源及官方／第三方身份、实际 commit／标签或本地文件版本、实验入口与配置。未能对应时标明差异与未知，不能用同名项目替代。只读代码不要求先跑通训练；静态分析与实际运行结果分别记录。
4. 续读从实际索引取回阅读正文、可编辑图与预览、代码版本、上次问题和纠正。图或代码变化时只重核受影响路径；正文或附件缺失时说明缺口，不凭进度摘要重建。

若用户明确指定本次仅做局部资料核查，则读取原问题需要的代码／原文并返回证据，不强制重做主流程全图。其他阶段不能自动启动此用途；用户启动后保留原阶段、待办和恢复入口，核查结束仍停止等待。

## 二、先形成完整的代码全流程图

制作细则和配套示例入口见 [Drawio 制图约定](Drawio制图约定.md)：默认 draw.io、中文横向，先看标准图与连线正误图，再根据实际代码制作。先完成、核对、展示图，再开始逐组件的系统学习；初始澄清与补足画图所需资料可在此之前进行。

- 图从实际实验入口覆盖到最终输出，包含关键数据流、控制流、分支、循环、模型调用和主要实验环节；不只画模型方框或照搬论文架构图。
- 有训练和推理时分别画图，标清共享模型、权重保存／加载和阶段差异。若仓库另有评估流程则按实际关联表示；某条流程不存在就如实说明，不补造。
- 核心创新节点醒目标记，并建立“论文主张 → 图节点 → 实现符号”的对应。作者的创新声明与用户自己的创新评价分开；这里是学习范围，不代写笔记一。
- 缺代码、入口、配置或依赖中的核心实现时，保存已证实路径与具体缺口。完整图尚未成立时停在补资料／核图，不把概念草图或未知路径称为完整代码图；用户主动调整范围时保存其决定和未覆盖部分。
- 展示可编辑的 `.drawio` 与可直接查看的预览。图已保存、结构已核对、预览实际可读分别记录；只有 XML 存在不算已完成图文学习准备。

完整指选定实验及配置的端到端流程，不要求枚举仓库全部工具、全部消融组合或每一行语句。会影响流程正确性与论文核心创新的分支必须覆盖，辅助代码可合并为职责明确的节点。

## 三、按图由整体到组件学习

| 层次 | 学习内容 | 有效理解的依据 |
|---|---|---|
| 整体 | 实验要解决什么、输入输出、训练／推理的全程、主要组件分工和连接；先沿总图串通 | 用户能说明主线、数据去向及训练与推理的区别；03 已有效确认的部分可复用 |
| 各大组件 | 以图中节点为单位，解释作用、输入输出、上下游关系与实际类／函数；按需要展开子图 | 用户能说明组件为什么在此处、怎样参与整体流程；分支与迭代按真实关系理解 |
| 组件内部 | 内部结构、重要计算、关键参数／维度和公式，说明论文符号如何落到实现 | 用户理解会改变行为的关键组成、参数作用、已读取配置值和必要条件，不要求背诵所有参数 |
| 核心创新 | 对照实际论文逐项解释问题、机制、与基线的区别、公式／代码对应及在流程中的作用 | 每项有针对该机制的真实复述、回答或具体确认，关键误解已反馈纠正；“都懂了”不能覆盖尚未涉及的创新 |
| 回到整体 | 将各组件和创新节点重新串成训练／推理如何完成任务的整体 | 用户已有回应能支持连贯解释；已有充分回应时直接采用，不再强制重复测验 |

阅读路线由整体到组件，再到组件内部；用户插入问题先处理后回到图上当前位置。各论文的结构不同，不固定组件数、轮数、每页问题数或掌握分数。

深度以正确理解实验代码与核心创新为准：数据形状、关键条件、损失／优化关系、训练与推理差异、核心计算与参数含义等会影响理解时讲清；日志、进度条、通用样板、无关文件操作或不影响理解的微小实现可概括。用户主动追问的细节再展开。不能把核心创新以“细节太小”为由略过，也不要求穷尽所有普通工具函数。

公式辅助理解真实计算：给出所需符号、条件及真实出处，关联代码操作和图节点；代码与论文不一致时分别保留来源及影响，未能解释的关键差异列为待核查。未运行过的形状或行为若仅由静态推导得到，按推导记录。

## 四、每轮图文陪读与真实等待

1. **定位**：指出当前图页／节点、代码文件及符号、论文段落／公式和必要上下文；使用相同已核对版本，避免重复取文。
2. **讲解与思考**：将图、代码和论文放在同一条解释主线上，先给足必要说明，再提出当前最有用的问题。用户希望先自行阅读时给位置和关注点；需要帮助时直接解释，不把讲解拖成无休止猜答案。
3. **保存后等待**：把图版本、实际正文、问题、已理解范围与下一步交现有更新 Skill 保存回读，再发出问题并结束本轮。等待真实用户消息，不模拟其复述。
4. **据回应纠偏**：先回应用户当前疑问，再对照图及真实来源指出支持与关键偏差；必要时补基础或更新错误图。重要修正给出依据，保存纠正后等待真实反馈。
5. **接续当前阶段**：有足够理解依据时推进本阶段下一组件；关键误解仍在则用针对性问题核实。AI 已解释、纠正待确认、用户已有依据的理解分别记录。

理解核实可由一次综合表达覆盖多个组件或创新，不机械逐参数测验。用户明确跳过复述时尊重其要求，保存未验证范围；若因此仍缺核心创新的理解依据，只报告讲解／阅读结束，不报告完整理解通过。暂停不要求先回答最后一个问题。

## 五、证据、代码与图的记录

关键事实保留实际论文／附件版本及位置、仓库版本与文件／符号定位；有真实行号才填行号。PDF 页序和印刷页码有值时分开，只有文本锚点时使用真实锚点。抽取文本、OCR、远端回答、当前模型实际看过的页图和代码分别记录；译文辅助理解，关键术语回原文。

可沿现有工作区组织：

```text
文献/<文献标识>/
  阅读记录/<阅读标识>.md
  代码图/<图标识>.drawio
  代码图/<图标识>-<页名>.png
```

已有实际路径直接沿用。阅读记录保存任务／文献、材料 ID／版本、论文与代码身份、已核对实验配置、图文件／页／节点映射、学习路线与轮次、真实原话引用、解释与纠正、疑问和恢复点。

另在该记录内维护核心创新覆盖：每项主张的出处、对应图节点／代码／公式、已讲范围、真实理解依据与待解决点。图的节点来源映射和阶段完成／等待状态也放在过程正文与既有下一步中，不新增 01 必填字段。

04 只提供成果与增量；现有更新 Skill 统一保存阅读正文、可编辑图、预览和必要来源附件，并按“正文及附件回读 → 索引回读 → 当前任务入口回读”处理。代码图和阅读正文分别绑定实际版本；保存失败逐项说明。必要来源若仍依赖易失路径，记录尚不能恢复的部分。

阅读记录与代码图是工作区学习材料，不自动成为三笔记或正式图谱。个人想法保留用户来源，作者主张、技术事实与 AI 推断分开；不因画图或看懂代码就声称已经复现实验。

## 六、完成、暂停与后续阶段

第四阶段完整完成须同时满足：

1. 已核对选定实验的端到端 draw.io 图；训练与推理按实际区分，图与代码版本一致、预览可读。
2. 整体主线、各大组件、内部关键组成与参数／公式已有真实用户回应支持理解；不影响正确理解的细节可列为暂留。
3. 论文全部核心创新逐项有理解依据，影响其机制或全程理解的关键偏差已获得真实反馈支持修正。核心代码未公开或关键论文／代码冲突仍未解时保留相应缺口，不笼统称全部掌握。
4. 图、阅读正文、原话与必要定位已按既有机制保存回读，恢复入口清楚。

达成后简短报告“第四阶段已完成”，说明已理解范围及实际保存位置，然后结束本轮等待。用户可以继续本阶段讨论、要求中间存档或另行调用下一阶段并下令开始；AI 此时只准备三笔记等交接材料。

用户暂停或提前结束时，保存当前位置、图版本、核心创新覆盖、待回应问题和下一步，分别说明本次已做与未验证范围。中间存档使用更新 Skill，正式归档仅在用户明确调用 paper-archive 并下令开始后执行。

局部核查以实际证据是否回答原问题判断，返回内容、版本／位置、语境、支持范围、缺项和保存结果后停止等待；恢复原业务阶段同样由用户下令。新找文、修改阅读深度、切换论文／任务或进入 05／06／07／08，均按阶段控制约定处理。
