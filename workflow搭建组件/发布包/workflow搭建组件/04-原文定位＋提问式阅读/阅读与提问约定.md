# 04 的原文阅读、提问与交接约定

供 [paper-read-with-questions](Skill草稿/paper-read-with-questions/SKILL.md) 执行时读取。本文件为已部署执行规则。本文件维护 04 执行细节；共享字段与保存顺序继续以 [状态约定](../01-对齐当前状态/状态约定.md)、[临时成果约定](../01-对齐当前状态/临时成果约定.md) 为准，01 不作补充或修改。

## 一、进入与恢复

1. 使用已有运行模式、状态目录、任务／文献标识、阅读深度、目的、材料身份与版本、工作区索引及规则。设计审阅读组件样稿；试跑使用隔离副本；实际阅读使用已指定正式位置。缺少会改变当前动作的信息时才补充。
2. 接收 03 的已明确选择、原文定位、用户实际理解依据、疑问、类比纠正及相关材料版本。用户直接提供论文且明确要求阅读时可直接进入，必要上下文由现有对齐 Skill 取得；不补造经过 02／03 的记录。
3. 独立进入也读取最新适用行为规则，已有目标、背景和明确选择直接沿用。长期纠正仍按 [行为规则约定](../01-对齐当前状态/行为规则约定.md) 交现有更新 Skill，当前论文的临时要求只随相关任务恢复。
4. 续读先从实际索引取回当前论文的阅读正文、上次问题、相关原话、纠正和材料版本。核对附件身份，带着待回应问题继续；已回答且仍有效的内容无需重问。正文缺失时记录缺口，不根据一句进度摘要重建复述。

完成入口核对后，应能说明：当前论文和版本、本次目的、已有理解依据、从哪个问题继续，以及必要资料缺项。资料不足可先做有依据的部分。

### 调用用途与返回

同一 Skill 按实际任务采用两种用途，Agent 根据已有请求判断，不增加用户选模式的环节：

| 用途 | 进入条件与动作 | 返回／停留 |
|---|---|---|
| 陪读 | 用户要求理解原文、模块或公式，按下列第二、三节阅读复述和纠偏 | 主流程按本次阅读目标推进；其他阶段借用局部陪读时，解决该问题后回到原阶段待办 |
| 资料核查 | 03／05／06／07 等只需定位、核对词句／参数或取得证据范围；直接按第四节读取核对 | 返回真实内容、来源版本／位置、必要语境、支持范围、缺项和保存结果，原阶段继续判断；不要求用户复述，不默认交 05 |

调用时保留原阶段、待解决问题和结果返回后要继续的动作。它们写入 04 过程正文及既有下一步，不增加 01 字段，不切换成另一项独立阅读任务。核查成功不增加用户掌握范围；证据不足也按原问题返回缺口，不能为了完成核查临时改成陪读测验。

确需用户澄清来源／用途时，保存已有材料、问题及返回点后等待；暂停恢复仍沿原用途接续。用户明确转为局部陪读时才进入陪读循环，保留返回点。核查期间原有陪读轮次、待回应问题与理解记录继续保留，不被核查结果覆盖。

## 二、陪读时按层次组织阅读

**先整体框架 → 沿信息流读关键模块 → 按需深入细节 → 回到整体串联。** 每层使用下节的同一陪读循环，不以读完整篇作为首次纠偏时点。

| 层次 | 阅读范围与提问重点 | 调整方式 |
|---|---|---|
| 整体框架 | 定位问题定义、输入输出、总体图或实际描述模块的文字；请用户说清目标、模块分工及连接 | 以具体表达检查主线，不只问“懂了吗”；03 已有有效主线复述时复用；宏观疑点可带到模块中解决 |
| 关键模块 | 按真实输入到输出的信息流，读一个模块及其必要上下文；问输入、作用、输出、上下游关系 | 分支分别说明、汇合处再串联；循环按真实迭代关系处理，不硬改为单线因果；训练与推理涉及不同时分别定位 |
| 必要细节 | 对本次用途重要的机制、符号、公式、参数或实验依据 | 解释所需前提后回到原文；用户指定公式可直接进入；未影响主线的细节记为暂留 |
| 整体串联 | 请用户把已读部分连成方法如何解决问题的主线，按目的关联证据 | 有关键断点时回读相应位置；已有回应足以说明主线时直接采用，不再强制重复测验 |

“一部分”按完整意义划分，可以是一段、一张关键图、一个模块或公式组；相关符号、条件或相邻模块不可缺时一并读取。默认每轮聚焦一个主要问题，用户可要求综合讨论，不固定每页提问次数、阅读轮数或掌握分数。

## 三、陪读每轮动作与真实等待

1. **定位并核对**：按下一节取得能支撑当前问题的原文及必要上下文，分清实际事实和缺项。已有材料版本未变且定位可靠时复用，避免重复取文。
2. **给阅读任务**：向用户说明读哪里、关注什么，再提出当前主要问题。默认先让用户阅读思考，答案留给其表达；提示只补足执行阅读的必要前提。
3. **保存待回应内容并停下**：把本轮定位、阅读任务、问题和当前阶段交现有更新 Skill 保存并回读，再向用户发出阅读邀请。此处结束本轮回应，等待真实用户消息；文件中的“继续”步骤不授权 AI 自行编出复述或跨过等待。
4. **接收真实回应**：保存相关原话及来源。用户可以复述、提问、明确求助、跳过或暂停；分别处理。用户问问题时先回应该问题，不把提问本身当作已理解。
5. **对照原文纠偏**：指出复述中有依据的部分，定位影响主线的偏差，解释原文为何支持修正；必要基础随读随补。关键事实有出处，背景知识及 AI 推断分别标明。涉及类比时沿用 03 的真实模块映射与边界。
6. **选择下一动作**：仍有关键误解时，给一个针对性提示或追问；已清楚时继续下一部分；次要疑问暂留；材料不足取得所需资料或停留待补。新的解释、纠正、回应和下一问题先增量保存，再按第 3 步等待。

用户明确求助时可以直接解释，明确跳过复述时尊重其要求并保存未验证范围。把“读过”“AI 讲解过”“用户复述有依据”“用户明确确认的范围”分别记录，不自动等同于掌握全文。纠正已给但用户未回应时记“纠正待确认”，不能写成误解已消除。

暂停不要求用户先回答最后一个问题，保存待回应问题、正文和恢复入口即可。保存失败时说明实际未保存部分；不依赖该写入的阅读可继续，失败状态持续保留。

## 四、原文证据与工具读取

| 项目 | 执行要求 |
|---|---|
| 论文与附件身份 | 有 Zotero 时记录实际库／条目／附件引用；否则用可定位本地附件、正式链接或其他实际来源，题名只作辅助。不同版本分开核对 |
| 位置 | PDF 页序与印刷页码分列；章节、段落、图／公式／表编号和代码位置按取得情况记录。只有摘录锚点时用真实锚点，不制造页码 |
| 当前原文范围 | 保留关键片段／可恢复来源与必要语境。问题依赖符号定义、假设、图例或实验设置时同时读取，不以孤立句子推出超出范围的结论 |
| 证据类型 | 分清抽取文本、OCR、原始代码、远端工具回答、当前模型实际读取的页图；远端回答不能改标为当前模型看过图 |
| 图表和公式 | 关键结构或符号不清先取得清晰页图、可靠文本或其他可读资料；能力不足明确待补。工具 schema 与模型视觉按实际环境，不猜工具参数 |
| 作者主张与解释 | 区分作者报告、可核实机制、通用背景、AI 推断和用户判断。反事实问题如“移除模块会怎样”只按原文消融结果或明确推断处理 |
| 译文与版本冲突 | 译文辅助理解，关键术语仍回到原文。新证据修正旧解释时保存来源和版本差异，不静默用新版位置覆盖旧附件记录 |

只有题名或模型记忆时先找可读资料；只有摘要时可以读摘要支持内容，但不能据此详解未取得的具体模块或实验。用户已选精读而缺全文时保留其选择及待补项。

工具职责是取回资料，本 Skill 负责阅读与教学决策。新找文或引用链问题交 [02 Skill](../02-找论文并分层/Skill草稿/paper-find-screen/SKILL.md) 通过真实 Undermind MCP 搜索。已有论文的资料读取无需为证明搜索而启动新找文；当前材料来源如实标注。

## 五、阅读记录与复用现有保存入口

04 提交的是现有更新 Skill 已接收的普通成果正文与进展增量，不新增 01 字段或专用保存动作。工作区内可组织为：

```text
状态目录/任务成果/<任务标识>/文献/<文献标识>/
  阅读记录/<阅读标识>.md
```

已有对应记录路径直接沿用。同一阅读记录内追加有稳定编号的轮次，实质变化才递增材料版本；任务、论文或附件版本不同的内容明确区分。路径和下列内部字段由 04 维护，不要求修改 01 来枚举材料类别。

| 记录部分 | 最少内容 |
|---|---|
| 标识及来源 | 任务、文献、阅读材料 ID／版本、日期、附件身份及版本、当前证据范围，已有 03 解释／评估引用 |
| 调用用途及返回点 | 陪读或资料核查；被其他阶段调用时保存原阶段、原待办及返回后动作。核查记录与原陪读轮次分开，不覆盖其待回应问题 |
| 阅读路线 | 本次目的和深度、当前整体／模块／细节／串联位置、已读与待读范围；这不替代 01 的任务状态 |
| 每轮正文 | 轮次 ID、原文位置和证据引用、阅读任务与问题、真实用户原话引用、AI 讲解与纠正、各自依据 |
| 理解和疑问 | 用户实际复述支持的范围、明确确认范围、待回应、纠正待确认及资料待核查；疑问各自保留解决依据或下一动作 |
| 恢复与材料引用 | 当前待回应问题原文、上次纠正、下一步；自然产生的三笔记／写作／引用／关系素材入口与来源 |
| 保存结果 | 材料正文实际版本与路径、索引及当前入口的分项核对结果；正式归档另记，不由阅读记录自行宣告 |

向 [更新 Skill](../01-对齐当前状态/Skill草稿/paper-update-state/SKILL.md) 提供：运行模式、状态目录、事件（重要进展／成果暂存／收尾等）、任务／文献、已读取版本、材料 ID／版本、原话及实际正文／路径、字段依据和下一步。资料来自工具或对话，不要求用户填表。

更新 Skill 写前核对最新文件，先保存原话和正文并回读，再更新索引和当前任务，返回真实路径、版本及分项结果。04 只依据回执报告已保存；正文成功而索引失败时保留真实正文位置和待修复状态。既有索引泛化保存材料路径，恢复仍取相关正文；不新建平行索引或第二套学习档案。

阅读记录是工作区过程材料，默认不成为正式三笔记，也不复制一套 Zotero 正式笔记。自然形成的个人想法保留用户原话；作者自述限制、技术事实及 AI 候选分别标明来源。

## 六、完成、暂停与阶段交接

资料核查按原问题判断结果并返回原阶段，已核对、待补及保存失败分别说明，不以用户理解为完成条件。下列理解标准只用于陪读。

陪读按本次目标判断完成：用户的真实复述或明确确认可说明当前要求的主线／关键机制，影响本次目标的实质偏差已有用户回应支持修正，材料及下一步已保存。只确认主线就只记主线；未读的细节保持未读。非当前目标的剩余疑问可以暂留，不要求所有组件、公式和参数全部弄懂。

仍有影响当前主线的误解时，记录实际进展并继续纠偏，或按用户选择暂停／调整范围；不能因为 AI 已给出纠正就报告理解目标完成。

用户主动结束、暂停、改变深度或跳过复述时，分别记录其决定及实际理解范围。允许按其用途结束阅读，不能把“用户要结束”推断为全文理解通过。只有待回应问题时保持待回应，不自行宣称本次理解目标已达成。

| 接收方／事件 | 交接或保存什么 |
|---|---|
| 暂停与续读 | 原话、阅读正文、待回应问题、关键纠正、实际位置、规则与材料版本；恢复时读回这些内容，再继续当前问题 |
| 切换论文／任务 | 交现有更新 Skill 保护原材料、索引和必要任务快照，再切换；恢复原论文时不混用新论文位置 |
| 返回调用方 | 资料核查或其他阶段借用的局部陪读返回原阶段待办，交真实结果／缺口与版本，不继续走主流程的 04→05；暂停则先停留，不替原任务宣称完成 |
| [05 三笔记分别记录](../05-三笔记分别记录/Skill草稿/paper-record-three-notes/SKILL.md) | 主流程阅读结束且需要整理时保持 04→05；交本轮范围、已保存原话与技术素材、确切出处和版本、未核实细节。笔记一／三保留用户判断，笔记二沿原有约定关联笔记一 |
| 02 补搜 | 所需新论文问题、种子及方向、已有证据和缺口，不以模型记忆生成已发现候选 |
| 03 调整选择 | 用户明确改变深度时交现有更新 Skill 更新同一评估，保留来源和原因；不因阅读困难擅改用户选择 |
| 06、07、08 | 按实际所得和用户本次用途交素材与版本。正式归档由 08 处理；阅读结束与归档成功分别记录 |

05 已有未部署草稿，未部署／不可用时只准备交接，不声称已运行其 Skill；04 中只及时暂存自然形成的素材，不默认穿插三笔记整理。用户明确要求临时整理时按其指令处理，并如实说明实际执行范围。
