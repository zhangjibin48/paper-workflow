# 两个状态 Skill 的共享约定

开始与收尾先遵守 [阶段控制约定](../../阶段控制约定.md)。本文件中的跨业务阶段交接仅准备材料，用户明确调用目标 Skill 并下令开始后才执行；日常读取与保存仍返回当前阶段。

适用：对齐、更新及其调用方。此文件是状态字段和保存规则的统一依据；本文件为发布包执行约定。

## 路径与写入归属

- 调用入口提供 `运行模式` 与 `状态目录`。审阅读组件样稿；试跑读写独立副本；正式运行读写已配置的正式目录。状态目录已有时直接使用，缺失时才补充。
- 共用记录包括 `学习档案.md`、`当前任务.md`、`行为规则.md`，以及 `任务成果/任务标识/` 下的持久工作区。对齐 Skill 负责读取，更新 Skill 是这些资料的唯一写入入口；业务步骤提供增量，08 返回归档回执。
- 任务切换或恢复时，更新 Skill 保存 `历史任务/任务标识-版本.md`，并返回实际路径。快照保留进度、工作区索引位置、材料版本与未归档清单，并记录原当前任务文件的实际目录。快照位于不同目录时，本地引用按快照目录重新定位，或提供可直接读取的绝对入口；写后从快照实际取回索引及相关正文，不能将原相对链接原样搬入历史目录后宣称可恢复。学习档案、行为规则和工作区留在原位置，不能只保留一份失去材料引用的摘要。
- 三笔记的已归档正文以 Zotero 为准；尚未归档的用户原话、笔记草稿、选文判断、写作素材等按 [临时成果约定](临时成果约定.md) 保存在持久工作区。当前任务记录索引，不承担正文，但正文必须有落盘位置。
- 明确的长期行为纠正由更新 Skill 保存到 `行为规则.md`，对齐 Skill 每次开始加载并向后续步骤交接，详见 [行为规则约定](行为规则约定.md)。08 的详细归档记录和选文索引由归档 Skill 维护，状态记录只引用其实际结果。

## 学习档案

每个有值的项目至少能说明其依据来自用户陈述还是既有记录，以及记录日期；本轮迁入时间与原陈述时间分开。

| 字段 | 含义与维护方式 |
|---|---|
| 记录性质、版本、最近更新 | 区分样稿与正式数据；实际变更成功后递增版本；无变化不递增 |
| 专业与学习基础 | 保留用户自述与已明确的进度；讲解过某概念不能直接改成已掌握 |
| 已读范围概要 | 记录已知阅读范围；具体文献以后按索引检索，未知保留为未知 |
| 兴趣与研究范围 | 允许宽泛、多个并存；用户改变方向时更新 |
| 投稿与算力约束 | 保存用户目标及时间表述；相对期限不擅自换算为新的截止日期 |

学习档案只保存学习背景。长期行为偏好以 `行为规则.md` 的启用条目为准，由更新 Skill 维护，不依赖聊天记忆，也不自动改写 Skill 源文件。向用户回复简练与设计文档充分的适用边界一并保存。

## 当前任务

| 字段 | 必要内容 |
|---|---|
| 记录性质、版本、最近更新 | 各文件分别维护，避免把其中一个文件成功当成整批记录与成果已保存 |
| 任务标识、目标、类型 | 首次实际任务时分配可稳定复用的标识；区分方向探索、专题找文、单篇阅读等 |
| 任务状态 | 未启动／进行中／暂停／完成；完成表示已满足本次目标和深度，仍可留下待研究问题 |
| 阅读深度与范围 | 筛读、精读、复现检查或待定；只在已知时填写 |
| 论文定位 | 有 Zotero 时记录库标识、条目 key；当前附件另记附件 key 或路径。接入前允许 DOI、链接或本地文件，题名作辅助识别 |
| 当前阅读位置 | 对应哪份附件、PDF 页序、印刷页码（如有）、章节／图／公式。尚未核对的定位标为待核对 |
| 已理解内容 | 用户复述或明确确认的理解及依据；AI 解释与候选结论另作待核查内容 |
| 未解问题 | 保留尚未解决的疑问与必要定位；只有得到解决依据才移除或标记已解决 |
| 工作区索引与活跃文献标识 | 指向 `任务成果/任务标识/索引.md`，定位当前论文、相关材料文件和准确版本；同一专题任务可包含多篇论文 |
| 未归档成果与保存结果 | 索引中的用户原话、三笔记草稿、选文记录、写作范例、引用和关系候选等；分别说明材料是否已落盘、是否已正式归档 |
| 已加载行为规则 | 本次实际读取的规则文件版本与适用规则 ID，正文以行为规则文件为准；恢复旧任务时仍加载最新启用规则 |
| 本次临时行为要求 | 明确仅当前任务或当前论文适用的要求、范围和来源；随相关任务恢复，不能自动升级为长期规则 |
| 下一步 | 足以在新会话执行的动作；确实等待用户决定时写清待决定什么 |
| 归档状态与回执 | 未申请／待处理／部分完成／已核对完成／失败待处理／本次不需要；关联 08 回执，保留未完成项 |
| 最近保存结果 | 对本次实际写入分别记录成功、未变化、部分成功或失败；下一次读取仍核对文件本身 |

任务状态与归档状态分别维护。例如阅读已完成，但笔记写入失败时，可记“任务完成、归档部分完成”，不能笼统写成全部完成。

## 对齐给后续任务的交接

- 本次目标、任务标识与当前状态；任务还未建立时明确标注。
- 与当前动作相关的背景与硬约束，不携带整份历史。
- 文献定位、阅读位置、未解问题和下一步。
- 工作区索引、当前论文相关材料及未归档版本；先取回相关原话与草稿，不能只凭进度摘要恢复内容。
- 当前启用且适用于本次任务的行为规则、版本与本次例外。执行过程中收到明确长期纠正时，保存后立即刷新交接。
- 尚未解决的冲突／缺项，以及是否已有未保存变更。

有关键缺项就针对该项询问。可并行推进的普通工作照常进行；AI 的猜测只作为候选，不覆盖记录中的已确认事实。

## 更新 Skill 接收的变更

调用方提供：运行模式、状态目录、触发事件及受影响资料；涉及阅读时附对应任务和论文、已读取版本、字段依据、相关原话、成果正文／路径、材料 ID 与版本、疑问和可用回执。全局行为规则更新可以独立运行，无需为了保存纠正创建阅读任务。选文材料遵循 [选文记录约定](../08-归档与关系图/选文记录约定.md)。

资料可以来自当前对话或工具回读，不要求用户另填表。首次建档、纠正、成果暂存、长期规则更新、切换／恢复、归档回执和收尾是不同事件；只更新受影响的字段。只提交“新增了笔记草稿”的摘要不算正文已保存。

## 保存规则

1. 写前重读实际文件。当前任务标识或版本与原读取不同，应把本次增量与最新记录比较；能明确合并就合并，有相互矛盾的内容才询问，保留现有内容到冲突解决。
2. 增量写入，保留未改动的背景、疑问与资料引用。用户明确纠正的值替换旧值，保留来源及更正时间；AI 推测保持候选身份。长期纠正和仅本次要求分别按行为规则约定处理。
3. 有成果正文时，先保存原话、相关草稿与必要附件并回读，再更新工作区索引，最后更新当前任务指向已核对的材料版本。正文回读后若再修改，包括补材料 ID、来源等元数据，需重新回读修改后的当前版本，再更新索引；先前版本的回读不覆盖后续修改。仅正文或仅索引保存成功时，分别报告，不宣称整批成果已保存。
4. 首次创建记录使用已有资料，缺项写明未知。切换论文保留旧文献材料与其索引；切换或恢复任务前先核对旧任务工作区、索引及历史快照，再更换当前任务。任一必要保存失败时保留原活跃记录，不让新指针遮住未保存内容。
5. 每个文件写后回读，检查内容、任务／文献标识和版本。多文件保存分别核对；一个成功、另一个失败时报告部分成功。暂停时同时核对本轮新增原话和未归档成果，不能只保存位置与下一步。
6. 回执引用真实工具结果、实际路径及所处理的材料版本。若工具成功提示后回读缺失，归档状态仍为待处理；重复处理同一回执时保留已有成功事实。归档旧版成功不能把更新的草稿也标为已归档。
7. 向调用方返回已保存字段、材料路径与版本、规则变更、仍未保存部分、待处理事项。更新 Skill 到此结束，支持保存返回当前阶段；独立更新结束后停止等待，另一业务阶段须用户启动。

历史快照、版本核对和写后回读由当前执行Agent逐项完成；没有后台保存或跨文件事务。
