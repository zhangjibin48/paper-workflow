# 长期行为纠正的承接

由 `paper-update-state` 维护状态目录下的 `行为规则.md`，由 `paper-align-state` 读取并交给正在执行的业务任务。当前使用 [行为规则样稿](状态样稿/行为规则.md) 审查字段，尚未部署。

## 规则结构

每条规则保存：稳定 ID、规则正文、适用场景、例外、状态、用户依据及记录日期、最近修改日期、替代关系。文件有独立版本，规则状态为启用／候选／已替代／停用。

明确的长期纠正直接进入启用规则。例如用户明确要求“以后别替我总结不足”，保存为：处理笔记三时先取得用户判断，AI 通过提问、核查和整理帮助表达；AI 自己的候选必须另标来源。原话和整理后的执行规则分开保存。

## 谁在什么时候保存

1. 当前对话中的 Agent 接收纠正，判断其适用范围与持续时间。用户使用“以后”“每次”等明确长期表达，或已明确要求长期保留时，交更新 Skill 保存，不重复索要确认。
2. 只针对“这次”“当前这篇”的要求，由更新 Skill 写入当前任务的临时行为要求，注明任务／论文范围及来源；原话可存工作区，续读按该范围取回，不自动升级为长期规则。
3. 若长期性或适用范围会实质改变后续行为且确实含糊，只询问这一处；本轮明确要求立即遵守。AI 猜测的偏好可作为候选，候选不作为以后执行依据。
4. 更新 Skill 读取最新规则，合并同义条目，保留来源；明确的用户更正替代冲突旧规则并记录替代关系。不同场景的规则与例外可以共存。
5. 写后回读，返回实际规则版本、启用条目和未保存项。调用方从本轮后续动作起应用已明确的纠正，不等下一会话。

保存规则失败时，本轮仍遵守用户指令，但明确告知尚未持久保存；不能承诺下次已经能够加载。

全局规则更新不依赖有活跃论文，也不应为了保存一条纠正虚构阅读进度。工作流设计阶段只维护组件样稿；实际运行时才写指定的正式规则文件。

## 下次怎样生效

对齐 Skill 每次开始读取最新的启用规则，先取共同适用条目，再按找文、陪读、归档等当前场景选择相关规则。与背景、任务和材料一起交接给业务步骤。

当前任务只记录本次实际加载的文件版本和规则 ID，规则正文仍以 `行为规则.md` 为准。恢复旧任务时重新加载最新启用规则，不能恢复成快照中的旧偏好。

会话中规则刚更新时，更新 Skill 返回变更，当前业务任务立即刷新相关规则。归档 Skill 如独立启动，也读取最新启用规则，避免绕过对齐入口后遗漏规则。

这些是用户行为约定的加载机制，不自动修改 Skill 源文件。将稳定共性经验改进成 Skill 规则属于之后的维护任务，须保留用户规则原意与适用范围。
