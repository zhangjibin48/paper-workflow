# 未归档成果的保存与恢复

开始与收尾先遵守 [阶段控制约定](../../阶段控制约定.md)。本文件中的跨业务阶段交接仅准备材料，用户明确调用目标 Skill 并下令开始后才执行；日常读取与保存仍返回当前阶段。

本约定解决“暂停但未正式归档”的材料保留。这里的临时成果保存到持久文件，不使用操作系统临时目录，也不依赖聊天历史仍在上下文中。

## 保存位置与维护者

运行时使用已指定的状态目录，结构如下。以下是部署后的路径约定；样稿仅供参考，实际读写使用运行入口配置的正式目录。

```text
状态目录/
  当前任务.md
  任务成果/
    <任务标识>/
      索引.md
      用户原话.md
      文献/
        <文献标识>/
          笔记一草稿.md
          笔记二草稿.md
          笔记三草稿.md
          写作范例.md
          引用候选.md
          关系候选.md
          解释记录/<解释标识>.md
          选文记录/<评估标识>.md
      附件/
      提交快照/<批次标识>/
```

只在产生相应成果时建立文件。一个探索或专题任务可以包含多篇论文；每份材料都绑定任务标识与文献标识，避免切换论文后覆盖同名草稿。尚无 Zotero key 时分配稳定的本地文献标识，之后补映射，原路径继续可追踪。

业务步骤把新增材料交给 `paper-update-state`；更新 Skill 是工作区唯一写入者。08 读取已保存版本并写正式目标，返回回执，由更新 Skill 更改工作区的归档映射。

## 各类材料保存什么

| 材料 | 保存内容 | 关键边界 |
|---|---|---|
| 用户原话 | 与任务有关的理解、疑问、创新／不足判断和明确纠正；逐条有原话 ID、任务／文献、记录时间与可用的对话定位 | 原句逐字保留，包括原有标点；写后与实际输入核对，引用时也不擅自补标点。AI 整理另列；没有消息 ID 就注明未记录，不能伪造定位或把改写当原句 |
| 04 代码图与阅读记录 | 实际代码版本、draw.io 可编辑图及预览、图节点与论文／代码映射、学习轮次及核心创新理解依据 | 图已生成、用户已理解和已保存分别记录；中间存档保留图与待回应问题，阶段完成后等待命令 |
| 三笔记草稿 | 三份分别保存正文、材料 ID、版本、来源原话 ID／原文位置、待核对内容 | 保留尚未成形的判断；AI 候选与用户结论分别标注 |
| 03 场景解释与选择 | 解释依据、教学场景、模块映射与边界、反馈和纠偏、用户选择及下一步 | 讲解正文保存后再等待反馈，选择增量写回原评估；不能把兴趣或 AI 建议自动写成用户决定 |
| 写作范例 | 值得学习的文章组织和分析方式、用户看法、原文位置 | 与技术方法分类分开；允许待核对和未命名范例 |
| 引用候选 | 短摘录、出处与位置、能支撑的意思 | 不能只留“下次挑一句”的摘要代替已有原句 |
| 关系候选 | 两端对象、拟议关系、已有依据与待核对点 | 继续作为候选，不自动进入正式图谱 |
| 选文记录 | 分区口径与年份、代码／数据、复杂度、复现条件、筛选结果与理由等固定字段 | 完整结构按 [选文记录约定](../08-归档与关系图/选文记录约定.md) |

保存关键原话和实际成果即可，无需全量复制聊天。来源是论文附件时保留附件身份和定位；如必要附件只在易失的临时路径中，应将必要文件复制到工作区附件目录并核对，或明确记录尚不能恢复的依赖。

控制方转交的内容先区分逐字原文与摘要。只有明确提供的真实用户字串才能逐字收入原话，并标注“控制方转交”、未知消息定位；测试目标、配置参数、控制方转述及AI拟定检索式各按自身来源保存。保存后逐条对照实际收到的原文字串，不能把控制方消息的整句引述改标为用户发言。

## 工作区索引

索引逐项保存：任务、文献、材料 ID、类别、实际相对路径、版本、来源引用、本地保存核对结果、正式归档状态、归档版本／目标、未完成事项。

正文是否已保存与是否已正式归档是两个维度。正文回读成功但索引尚未更新时，报告索引待修复并返回真实路径；索引存在而正文不可读时，不能称材料可恢复。

重要进展时先存原话与正文，回读后更新索引，再更新当前任务中的索引引用。暂停前检查本轮新增材料是否全部进入索引；保存失败项明确列出。相同材料只有实质变化才递增版本。

## 续读与切换

1. 对齐 Skill 从当前任务或历史快照找到工作区索引，核对文件是否可读。
2. 按当前论文、未归档材料与下一步取回相关原话和正文，注明实际版本；需要以前的用户判断时按来源 ID 取回原句。
3. 材料缺失、索引断开或正文版本不符时说明缺口，尝试索引记录的已保存路径；不能根据摘要编造原稿。仍可进行的阅读继续，依赖缺失材料的动作等待恢复。
4. 同一任务切换论文，只更改活跃文献，原材料留在原位置。切换任务前保存工作区及其引用，历史快照保留索引位置与未归档清单。恢复旧任务重新取回其工作区，不能只恢复位置摘要。

## 和正式归档的关系

准备归档时，更新 Skill 把本次提交的版本固定保存到 `提交快照/批次标识/材料ID-v版本.md` 并回读，索引记录提交路径。08 只读这份固定版本，避免同名最新草稿在归档期间修改后失去旧正文。源版本或快照不能读取时先修复入口，不用新版冒充旧版。

快照含相对引用时，保持源正文的版本与字节，同时保留可解析的目录或同版本别名，或明确记录引用基准与逐项目标映射。提交前从快照实际取回其引用正文；记录别名对应的材料 ID／版本，不把辅助入口算成新成果。

08 接收材料 ID、确切版本及提交快照路径，逐项保存并回读。回执至少包含“源材料 ID／版本 → 正式目标和核对结果”；更新 Skill 才能标记该版本已归档。

提交快照在归档成功后继续保留，作为已归档版本的依据，不自动清理原话、草稿或未归档材料。以后继续修改时形成新版本并标为待归档；已归档正文以 Zotero 等正式目标为准，旧草稿快照不作为另一份独立编辑的正式笔记。

若归档旧版本期间出现新版，回执仅关联旧版，新版仍待归档。正式目标部分失败时，本地全部材料继续保留。清理材料属于后续独立决定，当前流程不包含自动删除。
