# 07 的选句、核对、用途与交接约定

供 [paper-keep-writing-reference](Skill草稿/paper-keep-writing-reference/SKILL.md) 执行时读取。本文件为已部署执行规则。保存及正式归档继续复用 [01 状态约定](../01-对齐当前状态/状态约定.md)、[临时成果约定](../01-对齐当前状态/临时成果约定.md) 与 [08 归档约定](../08-归档与关系图/归档约定.md)，本轮不修改 01、08。

## 一、进入、查回与本次用途

1. 使用已有模式、状态目录、任务／文献、材料与附件版本、用途、相关规则及工作区索引。审阅读样稿，隔离试跑读写副本，实际运行使用已指定正式位置，不把组件材料当真实引用。
2. 取回 04／05／06 已保存的相关线索、原文位置与已有引用候选；直接提供句子或论文也可进入，不要求三笔记／分类齐全或重跑上游。必要上下文交既有对齐 Skill，独立运行也核对最新适用规则。
3. 用户已有用途、选句或收藏指令直接承接；委托 AI 挑选时按授权选择并注明受托来源。只请分析时保存候选／分析，不冒称用户已收藏或亲自认可。
4. 用途暂未明确时可先提出候选用途并标明 AI 建议，不要求完整写作计划。只有歧义会改变当前选句或支持判断时才针对性提问，先保存已有材料与问题，再结束本轮等待真实回应。
5. 只查回旧候选时取实际正文、原句、位置及原核对范围即可返回，不强制重取全文、重分析或递增版本；不把旧核对记录改称本轮重新核实。新增判断、来源版本变化或冲突需要相应补核。

默认每次聚焦一句，按用户需要可比较或保留多句。当前已读范围没有适合句子时可报告无所得，不凑固定产物，也不把局部未找到说成全文没有。

## 二、原句、来源与必要语境

| 核对项 | 要做什么 |
|---|---|
| 实际来源 | 核对文献及附件／材料身份、版本与实际读取范围。有 Zotero 时记录真实引用；没有时用实际文件／链接／可恢复来源，不伪造 key、DOI 或远端 ID |
| 原句文字 | 对照可读来源核对准确词句，保留原文语言。用户输入、摘录、译文和 AI 改写分开，不能把整理稿或记忆句子当作者原句 |
| 原文位置 | 记录真实章节、段落、句子锚点、图表或页序。PDF 页序与印刷页码有值时分开；没有页码用实际锚点，不虚填 |
| 必要语境 | 取足指代对象、假设／条件、范围、否定或转折及相关前后文。断开语境不足以判意义时保留待核查 |
| 证据类型 | 抽取文本、OCR、用户提供摘录、远端工具回答、当前模型实际看到的页图按真实情况说明，不相互冒充 |
| 版本差异 | 预印本、正式版、补充材料、译稿或不同附件的文字与位置分开，不沿用旧版定位冒充新版 |

用户只给一句而无可对照来源／上下文时，可以保留其原始输入及待核查项，不能把“输入存在”当作“原文和出处已核实”。用户提供可定位摘录及上下文时可核对其支持范围，独立来源真实性未核验的部分另记，不宣称已读正式全文。

必要时补同文资料；借用 04 时，定位／逐字核对用资料核查，用户确需理解时用局部陪读。携当前候选和返回点，按 [04 调用约定](../04-原文定位＋提问式阅读/阅读与提问约定.md) 返回本句用途判断，不默认复述或进入 05。OCR、断词、连字或符号不可靠时取清晰资料；无法确定就保留原始输入与缺口，不默改词义后称逐字一致。排版去断行应能回对原文；实质修订始终与原始输入分开。

保留必要短原句及语境；展示中的删节／补注明确标记，不改原始摘录。中文译文和 AI 释义另栏，不能把转译中文当作外文原句。

## 三、用途与可支持意思

| 用途 | 核查与记录 |
|---|---|
| 事实引用候选 | 说明拟支撑的意思，核对原句与上下文是否支持、支持哪些对象／条件、尚不能推出什么；作者报告不自动成为普遍已证事实 |
| 表达借鉴 | 说明该句怎样引入、转折、承接或界定范围，拟借鉴哪种表达；不是事实证据的句子不要附造技术结论 |

句子真实存在与目标意思得到支持分别判断。用途过强时指出不支持的部分，可以推荐范围合适的候选，但不修改原句迎合结论，也不把较弱支持称为原目标已达成。用户明确调整用途时记录真实变更来源。

必要的指代和条件可在语境栏保留，说明支持判断依赖哪些相邻内容；不能只摘前句、遗漏限定后句。未解决的含义或用途冲突保留待核查，不用文字流畅度代替证据。

不把 AI 讲过、已翻译、用户未反对或文件已保存写成理解／用途已经确认。用户原话、作者陈述、AI 建议和受托选择分别保留，新增个人判断须有真实依据。

## 四、转引或二手来源

句中引用／转述其他研究时，保存本轮实际读到的来源、原句及转引身份；被引标号或不完整书目信息只是线索。没有读到原研究就不称已核查原始结论，不编作者、年份、DOI 或全文位置。

若本次只留“当前论文如何介绍某项工作”的线索，可保存当前出处及转引范围。若用途需要直接证明原研究结论，保留待查，按实际需要交 02 通过合适的 Undermind MCP 路径发现／补搜，或读取已有可定位原研究，再交 04 核查相应内容。不因出现一个引用标号自动展开整轮找文。

元数据匹配、帮助说明或 AI 熟悉题名都不等于已读原研究。搜索及读取范围按实际记录，未取得原始证据不能提升核查状态。

## 五、一次执行与停留

1. 接续已有材料、句子／候选及用途，明确当前是新选、核查、查回还是局部更新。
2. 优先在已读且可定位的真实来源中选短原句。已有候选复用；只把笔记或写法分析作为线索，回来源核对文字，不默认重读整篇或另起搜索。
3. 核对原句、出处、必要语境与版本，再分别判断用途及支持范围；分不清时先保留真实缺口。
4. 形成候选正文，实际原句、来源、语境、译文／释义、用途、边界与选择来源分开。有必要问题时保存已有材料和问题全文，再提问并结束本轮，等待真实反馈。
5. 据新回应或资料只更新受影响部分，再交现有更新 Skill 保存回读。来源未变、只修改用途时保留已核对原句与定位；用途判断仍依据其语境，不自动改动引用文字。
6. 按真实范围报告：已核实且用途清楚的候选、仅已保存的待核查线索、已找到但不支持原目标、当前无合适所得分别说明。暂停保留问题与恢复入口，不强制归档。

两种用途共用同一 Skill，不新增写作环节。需要 06 组织范例时按用户需求交接，不将留句自动扩成整篇写法分析。

## 六、引用候选正文与分项状态

继续使用既有工作区中的“引用候选.md”，已有实际路径直接沿用，多个候选用稳定条目 ID 区分。每份材料带任务／文献、材料 ID／版本、日期及当前范围；每个候选至少保留：

- 候选 ID、实际原句和原文语言，来源文献／附件身份及版本、真实位置、实际取得的语境和证据类型。
- 输入来自用户时保留原始输入／原话引用；核对后的摘录、删节展示、译文、AI 释义分别记录。
- 用途类型、用户实际用途／AI 建议／受托选择来源、能支撑的意思、支持所依赖的条件与不支持的延伸。
- 原句／出处核对情况、用途匹配情况、待核查项与下一步；有转引时另记当前读到的来源及原研究缺口。
- 实际正文、索引和当前入口的保存结果；正式目标／归档源版本按既有 08 回执另记。

这些是 07 正文内部字段，不增加 01 必填字段。原句／来源待核查、用途不支持与本地保存失败不是同一种状态；文字已保存不自动提升前两项。

同一来源版本、位置和句子已有候选时复用稳定对象，不仅凭相同文字合并不同论文／版本；同一句不同用途可在原条目中分别保存，不复制多个失联副本。只更新受影响候选及材料版本，保留其他条目与旧表达来源，无变化不重复加版本。

没有实际句子或只记录无所得时不创建空候选文件，待补事项用既有任务下一步／索引说明；不造指向不存在正文的链接。

## 七、保存、恢复与正式归档

向 [现有更新 Skill](../01-对齐当前状态/Skill草稿/paper-update-state/SKILL.md) 提交模式、状态目录、事件（成果暂存／重要进展／收尾等）、任务／文献、已读取版本、受影响材料、原话及实际正文／路径、材料 ID／版本、字段依据、疑问和下一步，不直接写共享状态。

沿已有写前重读、原话／正文回读、索引与当前入口顺序保存。多文件部分成功时返回真实路径和失败项，不以回答正文或工具成功提示代替完整保存。必要来源只在易失位置时按既有机制保存可恢复材料，或明确仍不能恢复的依赖。

暂停／切换先保护正文、问题和实际版本，恢复读回对应原句及语境，不凭摘要重建原句。独立运行读取最新适用规则。已正式归档后修订需核对实际目标、草稿和回执版本，保护用户修改，不用旧本地稿覆盖未读正式对象。

需要正式归档时，更新 Skill 固定本批源材料和版本快照并回读，07 交 08 实际短摘录、出处、语境、用途及缺项。08 按既有规则写入引用入口、回链同一原文并回读，返回真实映射；旧版成功只对应旧版，新版继续待归档。Zotero 原稿和 Obsidian 入口的既有分工不变，不新增平行正式句库，不修改 01、08。

## 八、完成标准

原句及实际来源／位置已在所述范围核对、必要语境可找回、用途及支持边界清楚、选择来源真实，正文与索引回读成功时，才可报告本次对应参考句已核对并保存。

只保存未核查输入时明确“已保存待核查候选”，用途不支持时明确不支持，未找到合适句子按已读范围报告无所得；这些都不伪装成已完成可用引用。正式归档、用户理解与未来论文是否采用继续分别记录。
