# 归档资料与交接约定

本文件供 `paper-archive` 按需查阅，是三笔记、分类、关系图和归档回执的共同依据。本文件为已部署执行约定；正式目录按运行入口配置，不向组件样稿写入。

## 资料归属与标识

| 内容 | 主位置 | 归档记录保存什么 |
|---|---|---|
| 论文元数据、原稿、已有翻译稿 | Zotero | 目标库、论文 key、附件 key 或实际可定位引用 |
| 选文评估：已入库论文 | 同一 Zotero 论文下的独立“选文记录”附属笔记 | 评估 ID、任务、版本、选文记录 note key 及逐字段核对结果 |
| 选文评估：本次不入库候选 | `归档记录目录/筛选档案/评估标识.md` | 评估 ID、版本与实际路径；全部评估从 `选文索引.md` 找回 |
| 三份独立笔记 | Zotero 同一论文条目下 | 创新／具体方法／不足各自的 note key、最近核对结果 |
| 问题与方法分类 | Zotero | 本次新增或修改的类别与实际标签／集合映射；映射方式部署时确定 |
| 文献导航、写作范例与引用入口 | Obsidian | 导航文件、类别入口和原文定位；三笔记正文回链 Zotero |
| 两种论文关系图 | Obsidian Canvas | 图谱路径、稳定节点／边标识、对应关系记录引用 |
| 归档回执与恢复依据 | 指定归档记录目录 | 本次范围、逐项结果、已核对标识、失败项与下一步 |

正式归档按“库标识＋论文条目 key”关联对象；有附件时另记录附件身份。未建立 Zotero 条目前用 DOI、链接或本地附件作为临时依据，归档成功后补回映射。只知道题名时先核对作者、年份与附件，避免误写其他文献。

不入库候选的筛选档案使用稳定文献标识与评估标识，不强制建立 Zotero key。目标路径和工具能力按本次适用项要求，纯本地筛选归档无需依赖 Zotero／Obsidian。

## 未归档成果从哪里接收

08 从 01 的持久工作区索引取回源材料 ID、版本和实际正文，详见 [临时成果约定](../01-对齐当前状态/临时成果约定.md)。用户原话、笔记草稿、选文评估、写作范例、引用和关系候选不能仅靠当前任务摘要传递。

存在尚未保存的正文时，先交更新 Skill 保存和回读；提交前由更新 Skill 固定本批版本快照，08 从该快照归档。源版本不可读取时报告缺项，不从聊天摘要重新编造。08 本身不改写工作区；回执由更新 Skill 记回原材料的归档映射。

每项回执绑定源材料 ID／版本与正式目标。旧版归档成功不代表同时出现的新版也完成；更新 Skill 保留新版本待归档、用户原话和旧版快照。归档失败时全部未归档材料仍在工作区。

## 选文判断的正式归档

完整字段与存放、交接、回读方式以 [选文记录约定](选文记录约定.md) 为准。每份记录必须保留论文身份、分区体系及版本年份和学科口径、代码／数据链接和可用状态、复杂度、复现条件、筛选结果与理由、判断来源及待核查项；缺项以未知传递，不能在归档时丢掉。

08 对入库论文复用或建立“选文记录”附属 note，对不入库候选保存本地筛选档案；正文回读后再更新选文索引。回执保存 note key 或文件路径、评估版本与逐字段核对结果。筛读归档包含这一记录及适用分类，不以普通元数据或分类标签代替选文依据。

## 三笔记

| 笔记 | 内容来源 | 保存要求 |
|---|---|---|
| 一：方法创新 | 用户对创新、可能用途和可改进处的理解 | 保留用户原意和依据；AI 候选建议标明来源，不能冒充用户判断 |
| 二：具体方法 | 论文／代码里的函数、公式、参数及已核实的解释 | 保留附件、页码／章节／公式／代码定位；关联笔记一，不重复复制其用途背景 |
| 三：方法不足 | 用户认为的不足与判断依据 | 区分用户判断、作者自述限制和 AI 推断，疑点可以待核查 |

按阅读深度保存已有内容；尚未形成的笔记留待补充，不为了凑齐而创建空白或代写个人判断。笔记一暂缺时，笔记二可以先保存，但记住关联待补；以后笔记一建立再补链接。

若笔记一本来不在本次范围，未来补链接记为后续事项，不妨碍本次适用项完成；若笔记一本次需要却未能保存，则笔记一及关联属于本次未完成项，整体结果为部分完成。

修改前先读取目标笔记。优先复用归档记录中已核对的 note key，保留用户已有内容。映射丢失时先查该论文下现有笔记；只有明确找到对应类型才复用，多候选歧义需要解决后再写。不能仅凭一次请求超时就新建第二份。

## 分类、写作范例与参考句

- 研究问题和采用方法分别分类，允许多重归类；优先复用已有名称，新名称需要有实际区分价值。
- 写作范例保存文章怎样组织内容与展开分析，例如跨领域启发如何引出方法、扎实工作如何形成主线、实验现象如何逐层解释。此分类独立于技术方法与贡献类型。
- Obsidian 导航保存分类入口、范例说明及原文位置，三笔记正文以 Zotero 为准。引用候选保存短摘录、出处、位置和能支撑的意思；未取得原文时保留待核对。
- 修改分类采用增量方式，保留用户原有类别和无关标签。未指定标签／集合映射时，不自行重排整个文献库。

## 论文关系记录

每条关系保存：稳定关系标识、两端文献／方法及其映射、关系类型、方向、依据来源与位置、解释、相似与差异、判断来源、核对状态及更新时间。

| 类型 | 图中表达 | 进入正式图的条件 |
|---|---|---|
| 借用／发展／改进 | 前作 → 后作，标签说明具体关系 | 有能支持这一沿革的原文或代码依据；发表更晚、共同引用或用了同类方法均不单独构成沿革证据 |
| 方法相似 | 无方向连接，标签“方法相似” | 能说明共同机制及关键差别，并定位两侧资料 |
| 问题相似 | 无方向连接，标签“问题相似” | 能说明共同目标／问题及场景差异，并定位两侧资料 |

AI 推测先作为候选记录，核对后再进入正式图。正式关系被纠正时更新对应记录及边，保留修订依据；不因一次未找到证据就删除用户已有关系。

Canvas 使用稳定 ID 增量维护：已存在的论文节点和相同类型关系复用原 ID，新增项再布局；无关节点、手工位置、标签和边保留。边的标签包含类型与关系标识，详细依据保存在可取回的关系记录中。

[JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/) 定义了节点、边、标签和端点。相似图显式把两端设为 `none`，沿革图仅后作端设为 `arrow`；样稿用文字节点与依据说明卡，避免假装已有真实文献链接。

## 逐项状态与回读

| 状态 | 使用条件 |
|---|---|
| 待处理 | 属于本次范围，尚未执行 |
| 待补充 | 本次需要，但缺少材料或个人判断 |
| 待核对 | 工具可能已写入，尚不能从实际对象确认 |
| 已核对完成 | 实际对象已回读，身份、内容和引用均符合本次要求 |
| 失败待处理 | 操作或核对明确失败；保留原因与可行下一步 |
| 不适用 | 不属于本次深度或本次选择的范围，保留理由 |

每项至少核对目标身份、实际内容、引用和关键定位。Canvas 核对 JSON 能解析、ID 唯一、边端点存在、方向正确，再在 Obsidian 检查显示与链接。格式通过和显示通过分别记录。

本次所有适用项都核对成功时，可称本次归档完成；有待补充、待核对或失败项时称部分完成。没有本次适用项时无需新建空归档记录。

## 防重复与中断恢复

归档记录按文献标识保存对象映射和逐项结果；每个确认成功的操作及时记入。重试先查已有映射，再回读真实对象，只补未完成增量。回执丢失而工具可能已经写入时，先重新查询对象，不直接重建。

Zotero 成功、Obsidian 失败时保留成功的笔记／附件 key，后续只补相应入口或图谱。笔记二链接待补时，之后在同一 note key 上补链。归档记录写入失败时返回已经核对的真实标识和待保存回执，明确本地记录尚未落盘。

## 交给更新 Skill 的回执

至少包含：对应任务与文献、本次范围、源材料 ID／版本／路径、真实归档记录位置（或尚未保存）、逐项结果、成功对象引用、未完成事项、下一步和核对依据。选文项还包含评估标识、正式 note key 或筛选档案路径，以及选文索引写入结果。

更新 Skill 按 [状态约定](../01-对齐当前状态/状态约定.md) 保存归档摘要。08 不将“笔记已保存”推断成“用户已理解”，也不以“归档完成”自动清空阅读疑问。

08 独立启动时也读取指定状态目录中的最新启用行为规则，按 [行为规则约定](../01-对齐当前状态/行为规则约定.md) 应用相关条目；不能因为跳过开始对齐就遗漏长期纠正。
