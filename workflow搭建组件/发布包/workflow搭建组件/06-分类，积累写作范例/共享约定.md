# 06 的共享输入、类别复用、保存与交接

开始与收尾先遵守 [阶段控制约定](../../阶段控制约定.md)。本文件中的跨业务阶段交接仅准备材料，用户明确调用目标 Skill 并下令开始后才执行；日常读取与保存仍返回当前阶段。

供两个 06 Skill 执行时共同读取。本文件只维护共用规则；内容分类细节见 [内容分类约定](内容分类约定.md)，写作范例细节见 [写作范例约定](写作范例约定.md)。本文件为发布包执行约定，共享保存接口保持兼容。

## 入口与范围

1. 使用已有运行模式、状态目录、任务／文献、材料与附件版本、本次目标、工作区索引和适用规则。设计审阅读组件样稿；试跑使用隔离副本；实际任务使用已指定正式位置，不混用 DEMO。
2. 用户只要内容分类时只运行该 Skill，只要写法分析／收藏时只运行范例 Skill；需要两项时共享实际来源，但两份 Skill 分别由用户调用并下令开始，完成一项后停止等待，结果分别判断。不要求用户为单项任务补另一项资料。
3. 优先取回 02／04／05 已保存的相关事实、笔记、原话和原文位置，不重述背景、不默认重跑上游。直接提供可读材料时也能进入，不伪造上游经历或 MCP 来源。
4. 独立进入也核对最新适用行为规则；缺少必要上下文时交现有对齐 Skill。长期纠正按 [行为规则约定](../01-对齐当前状态/行为规则约定.md) 交更新 Skill，临时要求按相关任务／论文范围承接。
5. 续接从实际索引取回对应正文、版本、未解歧义和待回答问题；缺正文不能根据摘要编造旧分类理由或用户收藏动机。只有影响当前动作的缺项才询问。

入口核对完成后，应能定位当前材料、任务范围、已有分类／范例及必要缺口。06 不要求三笔记齐全，也不因筛读归类而强制精读。

## 来源与证据

- 每项实质判断保存“内容 → 实际来源／位置及版本 → 支持范围／待核查”。页码未取得时用真实章节／段落锚点，PDF 页序和印刷页码有值时分开，不补造页码、远端 ID 或笔记 key。
- 用户表达、作者报告、原文事实、AI 分析／推荐分别标明。用户的应用设想不变成论文已经验证的场景；AI 推荐不改标为用户亲自认可。
- 读取范围、抽取文本／OCR、远端工具回答与当前模型实际看过页图分别说明。分类和写法都不能从模型记忆补成已核实原文。
- 实验操作只有在实际材料明确说明时才记录“做了／未做”；资料未提及的操作记“当前片段未报告”，与全文是否实施分开。复用笔记或用户疑问时同样保留这一区别。
- 需要同文资料时用实际可用读取工具在当前阶段核查。确需 04 定位／核查或局部学习时，先保存当前问题／范例条目和恢复点，等待用户调用并下令；用途见 [04 调用约定](../04-原文定位＋提问式阅读/阅读与提问约定.md)。新发现／补搜同样等待用户启动 02，取得结果后也不自动恢复其他业务 Skill。缺工具或资料时报告真实缺口。

## 类别复用与增量

内容分类的“研究问题”“采用的方法”与“写作范例”分别维护语义，不因名称相近跨类型替换。只读取当前动作所需的已有类别、定义及实际映射，避免加载整库。

类别已有 ID 时沿用，未提供 ID 可用实际名称与类别类型定位；本地候选标识不能假作正式库标识。优先按含义和已有别名复用，而非只做字符串匹配；近义但定义不同的类别保持区分。

确有区别时提出新类别及简短含义、依据，不预建无内容分类。清楚的单篇归类或命名可直接形成建议并保存，无需逐个标签机械确认。歧义会改变检索结果时先保存候选与待决定点，再针对这一处提问并结束本轮，等待真实回应。

修正只提交受影响对象的新增、保留和拟替换部分，保留用户原有类别、手改和无关标签。正常单篇任务不自动合并／重命名类别或迁移历史条目；用户明确要求这类变更时按其具体对象和范围处理，不把已有授权反复当作待批准。

同类别只能提供关系线索；正式相似或沿革关系仍按 08 的原文／代码依据规则确认，不仅凭类别生成图谱。

## 工作区正文与现有写入入口

按 [状态约定](../01-对齐当前状态/状态约定.md) 和 [临时成果约定](../01-对齐当前状态/临时成果约定.md)，由现有更新 Skill 统一保存。06 提交普通成果正文，不增加 01 字段、不直接写共享状态。

可在同一任务／论文工作区组织为：

```text
文献/<文献标识>/
  分类记录.md
  写作范例.md
```

已有实际路径直接沿用。分类记录按轴保存条目，写作范例正文可包含多个有稳定 ID 的范例；只在产生实际内容时创建相应文件，不为未要求／无所得的另一项创建空正文。

共用最低字段：任务／文献、独立材料 ID／版本、来源材料与附件身份／版本、实际读取范围、类别引用及理由、判断来源、待核查事项、下一步。范例另有稳定条目 ID，局部更新不覆盖其他范例；具体分支字段在各自约定维护。

向更新 Skill 提供运行模式、状态目录、事件（成果暂存／重要进展／收尾等）、任务／文献、已读取版本、受影响材料及实际正文／路径、原话和依据、材料 ID／版本、疑问与下一步。资料来自实际对话或工具，不要求用户另填表。

写前重读，先原话与正文保存回读，再更新索引及当前任务入口；只在实质变化时递增版本。同一文件有多个条目时保留未修改条目。相同增量不重复创建类别／范例，没有新内容的等待不制造版本。

重要进展及时保存；必要提问或暂停前保存已有正文、原话与问题全文，再等待真实反馈。正文、索引或当前入口部分失败分别报告真实结果与恢复路径，不以回答正文或“工具成功”替代保存完成。

## 正式归档与后续交接

按 [08 归档约定](../08-归档与关系图/归档约定.md)：

- 正式研究问题／方法分类按用户最新指定使用 Zotero 文件夹（集合），沿设计分类记录对应存放，允许同一文献关联多个类别；具体层级、集合标识与既有对象映射在适配时核对，06 不自行重排全库。Obsidian 负责知识图谱及既有导航／写作范例入口，不替代 Zotero 分类存放；本轮不另增查回 Skill。
- 写作范例分类入口、范例说明和原文位置归 Obsidian，回链同一 Zotero 文献；不复制三笔记的正式正文。
- 归档前由更新 Skill 固定本次适用材料快照并回读，08 只读确切源版本，逐项写入／回读后返回真实映射，更新 Skill 再记回状态。
- 旧版成功不把新版标完成，部分失败保留成功对象和源正文。已归档内容需要修改时，先核对实际正式对象、现有草稿及版本，保护用户手改，不用旧草稿覆盖未读取的新内容。

向 08 交文献身份、分类／范例的实际正文、源材料 ID／版本／快照、已有类别映射和未完成项。尚无正式对象时不填虚构 key。

07 已有独立 Skill 草稿，需要留句时交实际原句、语境、位置及用途线索；未部署／不可用时只准备材料，不声称调用。写法分析和 AI 改写都不能当成原文引句。阶段顺序、用户判断边界与正式主库归属保持不变。

分类完成、范例分析完成、本地保存成功及正式归档完成分别判断。暂停恢复保留当前正文与问题，切换论文／任务先由现有更新 Skill 保护原材料，01、08 文件无需因 06 改动。
