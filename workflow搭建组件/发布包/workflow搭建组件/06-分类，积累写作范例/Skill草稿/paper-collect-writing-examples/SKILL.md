# 写作范例积累 Skill

先读取 [阶段控制约定](../../../../阶段控制约定.md)。完成本 Skill 后停止等待；另一业务阶段须由用户明确调用目标 Skill 并下令开始，日常读取与保存按支持动作处理。

本文件为发布包执行规则。执行前读取 [写作范例约定](../../写作范例约定.md) 和 [共享约定](../../共享约定.md)，未要求技术归类时不加载其分支。

1. 接续任务、文献／材料版本、实际范例范围与选择来源、已有正文及最新适用规则。必要上下文交 [对齐 Skill](../../../01-对齐当前状态/Skill草稿/paper-align-state/SKILL.md)；已有用户选择直接承接，受托推荐不冒充其亲自认可。只查回既有范例时可读取实际已存正文、位置与原核对范围后返回，不强制重新分析或增添版本。
2. 读取真实段落／章节及必要语境，局部不推成整篇。事实核查可在当前阶段用实际工具处理；确需 [04 Skill](../../../04-原文定位＋提问式阅读/Skill草稿/paper-read-with-questions/SKILL.md) 时保存条目、缺口和返回点，等待用户明确调用并下令开始。不编写未读取的组织或视觉细节。
3. 按实际顺序说明各部分如何安排与衔接，每一环节对应真实位置；区分原文、AI 分析和用户判断。技术数据流不充当文章写法，贡献类型不替换“讲故事”。
4. 写明借鉴内容、适用情形与边界，在独立写作范例类别中优先按含义复用，必要时提出新类。没有实质范例可无所得，不强套模板、凑固定产物或要求三笔记齐全。
5. 以稳定范例 ID 保存实际正文和来源，保留选择范围；只改受影响条目。正文、原话、材料版本、疑问与下一步交 [更新 Skill](../../../01-对齐当前状态/Skill草稿/paper-update-state/SKILL.md)，回读后据实报告。必要歧义先保存再提问，结束本轮等待真实回应。
6. 报告本次写作范例结果并停止等待。为 [08 Skill](../../../08-归档与关系图/Skill草稿/paper-archive/SKILL.md) 准备说明、分类入口与回链；需要留句时为 [07 Skill](../../../07-留一句写作参考/Skill草稿/paper-keep-writing-reference/SKILL.md) 准备实际原句及语境。执行任何另一业务 Skill 均等待用户调用及开始命令，AI 改写不作引用。

组织过程与原文映射、借鉴说明、类别、实际选择来源和范围明确，正文及索引回读成功才报告对应范例已保存。候选、资料待补、无所得和保存失败分别说明，不自动宣称全文分析、用户认可或正式归档完成。
