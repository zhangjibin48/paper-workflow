# 03 的解释、选择与交接约定

此文件供 03 Skill 执行时读取，统一规定论文事实、教学类比、用户决定和持久记录的边界。本文件为已部署执行约定。

## 证据与事实

1. 先核对论文和当前材料的身份、版本及可读范围。02 推荐理由是线索，具体方法主张仍要有可读取的摘要、段落、图、公式或代码支持。
2. 解释中的关键事实使用可追溯标识，保存“事实 → 来源／位置 → 核对状态”。有实际页码才填页码；只有摘要时以摘要段落定位，不生成不存在的 PDF 页号。
3. 区分作者报告、用户理解、AI 整理／推测和通用背景。一般背景可帮助解释，但不能被写成“本论文采用了这个模块”。用户提供摘录可以作为当前材料，独立核对状态如实标明。
4. 图像与公式按真实读取情况说明。远端工具回答、抽取文本、本机已看页图是不同证据范围；缺少关键证据时保留未知或待补，不承诺所选模型已经具备相应视觉能力。
5. 新原文与已有评估冲突时，保留旧版本，保存新的出处与修正理由；存在身份／版本歧义先解决相关部分，不静默替换论文。

## 场景怎样对应原文

默认用生活或用户领域的场景帮助用户理解，同时标明它是原论文真实应用、用户设想的应用还是教学类比。跨领域类比本身不证明方法已经适用于用户领域或可用算力。

映射应至少覆盖当前要解释的关键问题和机制，按实际资料填写：

| 映射项 | 应说明什么 |
|---|---|
| 场景中的问题 | 对应论文真实要解决的问题，以及当前目标为什么相关 |
| 场景中的对象／数据 | 对应真实输入、节点、变量或其他已知对象 |
| 场景中的动作／关系 | 对应模块的作用、相互连接及信息怎样流动；不能只列两个同名术语 |
| 场景中的结果 | 对应实际输出、任务目标或原文报告，区分目标和已验证结果 |
| 类比边界 | 哪些条件、机制或结论类比没有表达，哪些是未验证的迁移设想 |
| 原文依据 | 每项关键映射关联事实标识或原文位置；细节未知时映射也相应留空 |

类比导致错误理解时，指出错在何处并修改类比；不能为了保住故事继续扩展错误机制。用户希望技术表达或已有背景足够时可少用类比，原文映射与边界仍保留。

## 反馈与用户理解

- 先回应用户当前疑问，再决定是否补背景、换场景或进入原文。已有知识可直接使用，用户不懂的领域概念按需要解释，不要求重新报整份背景。
- 需要确认时可提出一个当前最有用的问题，不强制固定轮数、测验或统一口头复述。用户明确要跳过类比或直接精读时尊重其选择。
- 保存用户实际原话及 AI 对它的整理，二者分开。用户只说“有兴趣”不表示选择了精读；用户说“明白主线”仅证明其已明确确认该范围，不自动升级为整篇已掌握。
- 若用户表达创新、用途或不足，保留为用户原话／候选草稿；AI 自己的想法另标来源。三笔记的个人判断要求继续沿用。
- 明确的长期纠正交更新 Skill 按 [行为规则约定](../01-对齐当前状态/行为规则约定.md) 保存；当前论文的临时要求只在相应范围恢复，不能自动变成长久偏好。

## 选择字段与转换

记录分开维护：`AI 建议及理由`、`用户实际表达及原话引用`、`用户选择状态`、`实际阅读选择`、`选择变化原因`、`后续入口／缺项`。

选择状态只有“待决定”或“已明确选择”；实际选择可使用筛读、精读、复现候选／复现检查、暂缓、不纳入等与现有评估一致的表述。任务是否暂停、资料是否归档仍按 01 的独立字段记录。

| 情况 | 执行动作 |
|---|---|
| 用户没有决定或回答含糊 | 继续保留待决定；只有会改变下一步时澄清，不能默认精读 |
| 筛读所得已满足本次用途 | 保存选择和已有所得后可结束；需要分类时交 06 内容分类，需要正式保存时交 08，不经过 04 或强制整理三笔记 |
| 明确继续原文阅读 | 记录深度与待解问题，准备具体原文定位并交 04 陪读；不要求用户先完成额外测验 |
| 已选精读但全文／关键页尚缺 | 保存已明确的选择，下一步为取得所需材料；不降格为用户没兴趣，也不假称已可定位全文 |
| 只列为复现候选 | 保存候选意图、资源未知项和后续入口，本轮可结束；该选择不等于要求立即精读、核查全部配置或运行实验 |
| 明确要求现在做复现条件检查 | 按请求核对代码／数据／资源；仅缺原文事实时交 04 资料核查，确需用户理解时交局部陪读，核查后回到本次判断。新的论文发现交 02，已有资料可直接读取；实验执行另依明确任务处理 |
| 明确暂缓、不纳入或暂停 | 保存已有讲解、问题、具体选择和用户给出的原因后结束；未给理由时不替用户编造，不自动进入 04 或正式归档。暂缓／不纳入是选文决定，暂停是任务状态，分别记录 |
| 用户改变原建议或旧选择 | 在原评估上保留变更与原因；AI 原建议、用户旧决定和新决定来源清楚 |

## 由更新 Skill 保存的内容

按 [共享状态约定](../01-对齐当前状态/状态约定.md) 和 [临时成果约定](../01-对齐当前状态/临时成果约定.md)，03 向更新 Skill 提交解释正文、原话、材料标识与版本、来源位置、反馈、决定及评估增量，不直接写共享工作区。

解释记录的最低字段：

- 任务、文献、解释材料 ID、版本与日期，来源材料／附件身份及已读取范围。
- 关联选文评估 ID 和读取版本；直接提供论文而无评估时，由更新 Skill 建立一次，原始来源如实标为用户提供，不伪造 MCP 搜索。
- 关键事实及出处、场景性质、解释正文、模块映射和类比边界。
- 用户原话引用、理解反馈、纠正记录、尚未解决的问题。
- AI 建议、用户选择状态及实际选择、变化原因和下一步／所缺资料。
- 本地正文与索引保存核对结果；正式归档状态单独记录。

第一次解释有实质内容后先保存，再等用户反馈；后续新增疑问、修正或决定增量保存。更新 Skill 回读后，03 才能报告已经保存。正文保存失败但对话可继续时保留未保存状态，暂停前明确列出，不能仅保存一句进度摘要。

## 按选择交接

| 接收方 | 交接内容 |
|---|---|
| [04 原文定位＋提问式阅读](../04-原文定位＋提问式阅读/Skill草稿/paper-read-with-questions/SKILL.md) | 只在明确继续原文阅读或实际需要资料核查时进入；交用途、深度、来源版本／定位、真实理解依据、疑问、类比纠正与规则。复现条件的局部核查还交原判断与返回点，按 [04 调用约定](../04-原文定位＋提问式阅读/阅读与提问约定.md) 返回，不自动沿主流程整理三笔记 |
| 02 找论文并分层 | 需要新发现或补搜的具体问题、已有论文和证据缺口；引用链需求保留种子与方向，不强制新增全局搜索 |
| [06 内容分类](../06-分类，积累写作范例/Skill草稿/paper-classify-content/SKILL.md) | 筛读已足够且需要分类时，交实际问题／方法依据、原文范围、已有类别和版本；不要求先完成 04／05 或写作范例 |
| 08 归档与关系图 | 同一选文评估中的实际选择和依据，以及用户已形成的真实成果；讲解文稿默认保留工作区，不自动塞入三笔记 |

只取得摘要时交接其真实定位，原文具体页码可待补。04 组件或工具尚不可用时，报告已准备的交接资料及剩余缺项，不声称已经执行后续 Skill。未明确选择时停留在 03，不自动触发深度阅读、复现执行或归档。
